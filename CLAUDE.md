## Commit style
Do **not** add `Co-Authored-By:` trailers. The project uses multiple AI tools; selective attribution is misleading.

## Design rules
1. **One fact, one storage location.** No redundant persistent fields (`loc_nm`, `xnm`, `ynm`, `znm`, …). Expose coordinate views or helper methods instead.
2. **Canonical import model.** All source formats normalize to the same internal representation.
3. **Dataset ≠ viewer.** Viewers reference datasets as layers; datasets do not know about viewers.
4. **Separate channels in storage; overlay only at the viewer layer.** Each multicolor channel is its own dataset.
5. **Raw / derived / view state are separate.** `attr`/`mfx`/`mbm` is canonical; `derived` holds computed values; `state` holds persistent view/filter preferences.
6. **Python naming.** `snake_case` functions/variables/modules, `PascalCase` classes, `UPPER_SNAKE_CASE` constants.
7. **Minimal diffs.** Do not restructure unless explicitly asked.
8. **No silent fallbacks** that mask data or format errors.

## When implementing features
- Decide first: does the change belong in data model, import normalization, viewer layer, or script API?
- Prefer clear interfaces; do not leak internal structures into UI code.
- If a change affects source-format compatibility, update `docs/data-model.md` or document the limitation.
- For each task report: files changed · behavior changed · how to test · remaining limitations.

## Data model
A dataset holds: `attr`/`mfx` (materialized localizations), `mfx_raw` (all-iteration raw store), `mbm` (beamline/bead reference), `metadata`, `derived`, `state`. A group links related datasets (e.g. channels from one `.msr` file).

Canonical `mfx` keys: `loc`, `itr`, `tid`, `tim`, `vld`, `efo`, `cfr`, `dcr`, plus optional `eco`, `ecc`, `efc`, `fbg`, `lcx`, `lcy`, `lcz`, `ext`, etc.

- **`attr` vs `mfx_raw`.** `attr` is the materialized store the UI plots from (last iteration + valid, per the load preference); `filter_mask`/derived attributes (`den`, `siz`, `idx`, …) align to it. `mfx_raw` (`DatasetComponents.mfx_raw`, an `AttrStore`) is the **all-iteration, all-validity** flat store, populated by every loader. Row ordering is `loc_i_itr_j` at index `i*n_itr + j`; scalar-per-loc fields are `np.repeat`'d, per-iteration fields `.ravel()`'d, synthetic `itr = np.tile(np.arange(n_itr), n_loc)`.
- **Retrieval helper:** `core/loader.py::mfx_get(ds, attr, *, itr="last"|"all"|int, vld_only=True)` is the one way to read from `mfx_raw` with iteration/validity selection. It falls back to `ds.attr` only when `mfx_raw` is empty. Derived attributes are **not** in `mfx_raw`; `mfx_get` broadcasts each localization's last-valid value onto its raw rows (see Iteration browsing).
- Dataset Manager shows an **"Itr"** column (`last/N` or `all/N`) from `metadata["raw_num_itr"]` + `metadata["iteration_load_mode"]`. Double-clicking a 3-D dataset's **Dims** cell opens the Estimate Anisotropy dialog for it.

### Attribute lists & descriptions
User-facing attribute lists must go through `core/attributes.py` (`plot_attribute_names()`, etc.) so the UI respects Preferences. `plot_attribute_names()` builds candidates from `dataset.prop.attr_names` **plus** actual `dataset.attr.keys()` (protects dropdowns from stale `prop.attr_names`, e.g. `efo` present in `ds.attr` but missing from `prop.attr_names`). Trace-wise attributes (`siz`, `dur`, `len`) are track-level values expanded onto localizations — force trace aggregation in filter/histogram UI for them.

`core/attributes.py` is also the shared source for raw/derived attribute descriptions and aggregation descriptions used as dropdown tooltips. Keep MSR-reader wording and Preferences > Attributes derived-attribute descriptions in sync here, not duplicated in individual windows.

- **m2205 `iter_load="all"` keeps per-iteration columns 2-D `(n_loc × n_itr)` in `ds.attr`** (`efo`, `dcr`, `itr`, `sta`, …). Such attrs stay in dropdowns when `mfx_raw` serves them 1-D, and every window reads materialized per-loc values via `core/loader.py::attr_values_1d(ds, attr)` (returns `ds.attr` when 1-D, else the raw-store last-valid selection, which aligns row-for-row when `attr_matches_last_valid`). **Never `ravel()` a `ds.attr` column directly into a per-loc context.**

## Iteration formats
- **m2410**: flat per-localization, 1-D `itr`. Detected by `np.squeeze(itr).ndim <= 1`.
- **m2205**: nested struct or `n_loc × n_itr` style.
- Normalize both to one flat internal model; use selectors/index maps for `last`, `best cfr`, etc.
- Legacy MSR files may report as modern but have structured `mfx["itr"]` subarrays — normalize inside the modern loader path, not the OBF-only path.
- Two-channel DCR vs two-iteration DCR: sample 500 rows, check columns sum to 1.0.

## Canonical exports and MSR round trips
- File > Save raw exports and the MSR Reader export path share `core/save.py`; do not maintain format-specific serializers in the MSR plugin.
- Localization exports in `.mat`, `.npy` (NumPy), `.json`, `.csv`, and `.zarr` must use the canonical flat m2410 representation: one-dimensional top-level `itr`, `loc` recomposed from `loc_x/loc_y/loc_z`, `dcr` recomposed from `dcr_0/dcr_1`, and no derived/filter columns persisted as raw facts. Legacy nested fields such as `itr_itr` and `itr_loc` are not valid export output.
- Flat-column formats are reassembled through `core.save.columns_to_mfx_array()` before normal loading. `.zarr` is a directory dataset and is loaded by `core.loader.load_zarr()`; it requires `loc_x`, `loc_y`, `itr`, and `vld`, and must reject MBM-only companions rather than silently creating a malformed dataset.
- Large canonical JSON arrays and CSV tables use streaming/chunked I/O. Preserve the JSON array and CSV table formats while avoiding whole-file Python record lists.
- MBM/reference data is a separate companion component for non-`.msr` exports. Do not merge MBM fields into localization `mfx`; combined `.msr` output remains the dedicated path that preserves both components.
- Export must raise on missing or ambiguous required fields (`itr`, `loc`, `vld`) instead of inventing localization data. CSV reopening through the GUI may require the existing spreadsheet column-mapping confirmation; this is intentional and not a silent fallback.

## Iteration / validity browsing
Iteration/validity browsing is **implemented** (work lives on branch `stage-b-iteration-wip`). The Attribute Plot and Histogram windows have an iteration selector + `Valid only` checkbox, reading through the raw store. The contract:

- **Selector labels live in `core/iteration.py`** — `iteration_labels(n_itr, allowed=None)` → `last (Nth) · all [flatten] · all [stacked] · all [sum] · all [average] · (N-1)th · … · 2nd · 1st` (1-based; **fixed order for every *viewer* iteration dropdown, current and future**: last on top, the pooled modes, then individual iterations counting down; hidden when `n_itr==1`). `allowed` optionally restricts the **pooled** entries to a subset of `POOL_KEYS` (`flatten/stacked/sum/average`) — the histogram passes `prefs["plot"]["histogram_iterations"]`; the order never changes and `last`/individual iterations are never gated. `parse_iteration_label(label) -> (itr_selector, render_mode)` where `itr_selector` is `"last"`/`"all"`/`"sum"`/`"average"`/int and `render_mode` is `"single"`/`"flatten"`/`"stacked"`. `iteration_selector_label(selector, n_itr)` is the inverse (used to drive a dropdown from a stored filter spec).
- **Two kinds of pooled mode.** *Render pooling* (`all [flatten]` / `all [stacked]`) keeps one value per **raw row** and only changes drawing — viewer-only. *Value pooling* (`all [sum]` / `all [average]`) collapses each localization's iterations to **one value per localization**, aligned to the `last` selection rows, so it behaves like an ordinary per-loc attribute and **can be filtered on**. `loader.is_value_pool_selector(itr)` is the shared predicate; `VALUE_POOL_SELECTORS = ("sum","average")`. Consequence for the histogram: a pooled selection stays on the **materialized** path (`_is_raw_mode` returns False when `attr_matches_selection(last, vld)`), which is what keeps filter-edit + ROI bands working there. In the raw path the companion `tid` / filter mask must be fetched at `"last"`, never at the pooled selector (a summed `tid` is meaningless) — see `histogram_window._raw_values`.
- **The `Filter dialog` uses `filter_iteration_labels(n_itr)` instead**: `last (Nth) · (N-1)th · … · 1st · all [sum] · all [average]`. The render-pooling modes are omitted (they define no per-localization value), and the value-pooling modes sit at the bottom — a deliberate per-dialog order, not the viewer order above.
- **Photon (`eco`) weighting was evaluated and REMOVED from the histogram/filter** (2026-08). A `weighted=` option once multiplied any attribute by `eco`; validated against a real 2-colour ratiometric `.msr` it only had a statistical basis for `dcr` (a binomial proportion, var ∝ 1/N). Positions did **not** follow the CRLB 1/√N scaling at all (measured `d log σ_x / d log eco` = **+0.17…+0.49**, controlled for trace length, vs the predicted −0.5 — the scatter is dominated by drift, i.e. the `σ_fl` term of the Marin & Ries decomposition) and the effect was 0.09 nm median anyway; `cfr` is measured at one iteration so pooling it gives 0.25× the truth weighted or not; weighting a count by itself (`eco`) inflated it +14.7 %; and for every **derived** attribute the weighted average is an exact no-op (they are constant across a localization's iteration rows). So: do **not** reintroduce `weighted=` on `mfx_get` / `attr_values_for_selection` / filter specs. The surviving eco weighting is the **DCR channel separation** only — `analysis/attribute_channels.py::pooled_dcr_per_loc` / `eco_weighted_group_mean` (pyMINFLUX ECO-weighted pooling over `mfx_sequence.photon_iterations_for_dataset`), reached from the *Photon-weighted DCR* checkbox in `attribute_separation_dialog`. A stale `"weighted"` key in a saved filter spec/JSON is ignored, not honoured.
- **`attr_values_for_selection(ds, attr, *, itr="auto")`** is the single per-localization accessor the Filter dialog and the Histogram's materialized path share, so a filter row's `Iter` and the histogram it is authored on always show the same numbers. `itr="auto"` reproduces `attr_values_1d` exactly (cfr/efc at their effective iteration, else last-valid); `"last"` is the genuine global-max value (≈0 for cfr — use `"effective"` for that); an `int` gathers that iteration onto `ds.attr` rows; `"sum"`/`"average"` pool. `_values_on_attr_rows` is the materialized-view counterpart of `_broadcast_iteration_to_rows`.
- **`last`, single-*k*, `all [flatten]`** render identically to the default view (filled `BarGraphItem` / solid scatter); **`all [stacked]`** is the only multi-series renderer (one coloured series per iteration + legend + alpha scaled by `n_itr`). A stale cached `PlotItem.legend` must be reset in `_clear_raw_items`/`_clear_series` or the legend goes missing.
- **`idx` is synthetic** in `mfx_get`: 1-based flattened row position of the selected rows (`flatten`→1..N, `last`→`{n_itr,2n_itr,…}`, *k*-th strided). `mfx_row_mask(raw, itr=, vld_only=)` is the shared selection helper.
- **CRITICAL load-mode rule:** `ds.attr` content depends on the `iter_load` pref. With `iter_load="all"`, `ds.attr` holds ALL iterations and `ds.prop.num_loc` is the all-iteration count — so a `last` selection must NOT use the `ds.attr` fast path. `attr_matches_last_valid(ds)` returns True only when `ds.attr` IS the last-valid materialization; windows use the `ds.attr` path (with filter-edit/ROI) only then, else route `last` through `mfx_get(itr="last")`. Without this, `last` and `all [flatten]` looked identical under all-iteration loads.
- **Derived broadcast.** `den`/`dst`/`spd`/`dt`/`tim_trace`/`siz`/`dur`/`len` are computed at the last valid iteration and **duplicated** across each localization's iteration rows in `mfx_get` (NaN for rows whose localization never reaches the last-valid materialization, e.g. failed probes). Mechanism: (1) `loader.py::_raw_loc_id(raw)` lazily computes and caches a `loc_id` column in `mfx_raw` — groups = ascending-`itr` runs within a trace (stable-sort by `tid`, new group when `tid` changes or `itr` fails to increase). This one rule covers m2205 grids (`row // n_itr`), m2410 event streams (variable iterations per loc, interleaved traces, repeated final-itr rows), and single-iteration stores. (2) Per-loc source values come from `ds.attr` when `attr_matches_last_valid(ds)`, else from `ds.components.derived_last` — an AttrStore aligned to `mfx_row_mask(itr="last", vld_only=True)` rows, built by `_derived_last_from_raw()` in `load_dataset`/`load_from_mfx_array`/`load_json` whenever the materialization isn't last-valid (re-runs `_compute_properties` + `_add_derived_attributes` on the last-valid selection, so values equal an `iter_load="last"` load). `den` is appended to `derived_last` at dataset-add time in `main_window` via `local_density.py::compute_local_density_for_points`. (m2205 `iter_load="all"` keeps one `ds.attr` row per loc, so only m2410-style flat data takes the `derived_last` path.)
- **Invalid-inclusive loads (`only_valid_locs=False`) are first-class.** `ds.attr` then carries invalid rows (m2410 invalid rows have NaN coords — render/scatter finite-filter; m2205 invalid locs carry real coords). `metadata["includes_invalid"]` (`_attrs_include_invalid`) and `valid_num_loc` (`_attrs_valid_count`, vld-only) drive the Data window's `Locs (with invalid): <loaded> (<valid> valid)`. Default-path gating generalizes via `attr_materialized_selection(ds)` + `attr_matches_selection(ds, itr=, vld_only=)` (row-alignment via `_attr_row_selection`, which also covers the m2205-"all" quirk where attr rows align with `last` despite mode="all"); the materialized fast path (filter-edit, ROI) engages on the loaded view (e.g. `last` + Valid-only unchecked). It is deliberately NOT extended to `all [flatten]` on m2410-all loads (`prop.trace_idx` assumes contiguous tid blocks, which interleaved all-iteration rows violate).
- **Raw-store shape rule:** scalar-per-loc fields must be 1-D in `mfx_raw`; `_build_mfx_raw_m2205_unwrapped` ravels `(n,1)` MATLAB column vectors (a `(n,1)` `tid`/`tim` silently produced all-zero `derived_last` before this).
- **Persisted filters re-evaluate across iterations.** Filter definitions are saved to `ds.state["filter_specs"]` (`{attribute, mode, itr, lo, hi, lo_inc, hi_inc}`, written by `FilterDialog._apply_all`); `core/loader.py::mfx_filter_mask(ds, itr=, vld_only=)` re-applies them against the raw store so the same filter extends to any iteration / to invalid locs (NaN → False). Helpers `utils/filters.py::raw_spec_mask` / `raw_trace_aggregate` group by `tid` without assuming contiguous trace blocks.
- **A filter row is `(attribute, mode, Iter, bounds)`.** The Filter dialog's table columns are `On · Attribute · Mode · Iter · Min · Max · 👁 · ✕` (`_COL_*` in `filter_dialog.py`). `_row_iteration(row)` persists the **semantic** token: `"effective"` when a cfr/efc row sits on its measured iteration (so it re-resolves on a dataset with a different sequence), otherwise `"last"` / an int / `"sum"` / `"average"`. Changing Iter re-derives the Min/Max auto-range (`_on_row_selection_changed`) — the bound lives in a different value space, so keeping the old numbers would silently mis-filter. The 👁 (view) button passes the row's `itr` into `HistogramWindow.start_filter_edit`, which mirrors it onto the plot; a row targeting one **specific iteration** is edited with that iteration's values gathered onto the materialized rows (`_edit_itr` → `_current_value_itr`), so the drag region stays available instead of falling back to `last`.
- **Backward compatibility — a filter file/spec written before the Iter column existed.** A missing `"itr"` resolves to `"effective"` for cfr/efc (their measured iteration) and **`"last"`** for everything else (`resolve_spec_iteration`). The JSON preset key is `"iteration"` — **not** `"itr"`, which collides with the raw MINFLUX data-column name and would make `filter_io` misclassify the file as data. A leftover `"weighted"` key from the removed photon-weighting option is ignored (it is no longer in `filter_io.FILTER_KEYS`, and `is_filter_json_payload` matches on a non-empty key intersection so such presets still load). *(History: the pre-column default for non-cfr attributes was `"browse"` — evaluate the bound at whatever iteration was being viewed, so a localization's rows could split. It is now `"last"`, matching what render/scatter show; the two are identical on the default materialized view and differ only while browsing another iteration.)*
- **Known semantic gap (`last` = global max `itr`):** m2410 tracking files can mix sequences whose final loop iteration differs (`fnl`-flagged rows at itr 2 and itr 3 in one file). `mfx_row_mask(itr="last")` keeps only `vld & itr == global max`, dropping traces that loop at a lower final iteration; their rows show NaN for derived attributes in pooled views. A per-trace "final" definition (e.g. the raw `fnl` flag) would be a deliberate semantics change — not done.
- **`cfr`/`efc` effective iteration.** MINFLUX measures `cfr`/`efc` at only one loop iteration; their value at the global-max `last` iteration is 0/NaN. The 1-based measurement iteration is detected at load (`metadata["cfr_iteration"]`/`["efc_iteration"]`, via `_effective_iteration_column`, flat-m2410 + 2-D-m2205 aware) and shown in the Data window ("CFR 7th"). `core/loader.py::effective_iteration_for_attr(ds, attr)` returns its **0-based** index, or `None` when the attr is not cfr/efc **or** its effective iteration already is the last (so the change activates only when the materialized value would be wrong). `effective_attr_values_1d(ds, attr)` gathers each localization's value from its effective-iteration row (`_gather_iteration_values`, the inverse of `_broadcast_derived`, keyed on `_raw_loc_id`) onto `ds.attr` rows; **`attr_values_1d` returns this for cfr/efc**, so every consumer (filters, histogram materialized path, scatter colour) sees the real per-loc value instead of 0. `mfx_filter_mask` broadcasts a cfr/efc spec's effective value onto any browse selection (so a cfr filter doesn't wipe the view when browsing a non-effective iteration). In the **Histogram window** a cfr/efc attribute auto-selects its effective iteration (`_enforce_effective_iteration`; switching away restores the default unless the user manually browsed), and that single-iteration selection routes through the **materialized** path (`_is_raw_mode` special-case) so filter-edit/ROI keep working and the Iter label matches the values; the dropdown stays enabled as the manual override. `FilterDialog` needs no change — it already reads `attr_values_1d`.
- **Open enabler:** a single `_materialize_attr(mfx_raw, selection, *, to_display_units)` applying unit conversion + z-scale for any iteration selection, to centralize masking duplicated across `_parse_m2410`, `_parse_m2205_unwrapped`, `load_from_mfx_array`, `load_json`. EM-Gaussian `dcr` channel fit lives in `BACKLOG.md`.

## RIMF / z-correction & anisotropy
**Invariant (do not break).** RIMF (`cali.RIMF`, the z-scaling factor) is applied to z **only as a view** in `dataset.loc_nm` (`z = loc_z * 1e9 * RIMF`); the raw `loc_z` in `attr`/`mfx_raw` is **never** RIMF-baked, so RIMF can be re-set any number of times without double-correcting. Set it **only** via `dataset.set_rimf(value, *, source=...)`, which records provenance + history in `metadata["rimf_provenance"]` (`{value, source, applied_as_view, history}`); read via `dataset.rimf_provenance`. Sources: `default`, `auto (estimate anisotropy)`, `auto (out of range → 1.0)`, `fixed (preference)`, `2D (no z correction)`, `manual (anisotropy plugin)`.

- **Anisotropy / RIMF estimation must ALWAYS read raw z**, never `loc_nm` — use `analysis/trace_analysis.py::raw_last_valid_loc_nm(ds)` / `estimate_anisotropy_for_dataset(ds)` (raw `mfx_get(itr="last", vld_only=True)` × 1e9), so the estimate is independent of the dataset's current RIMF state (re-running is idempotent). The size estimate uses **MATLAB-aligned 0.1-width log-distance bins** (`floor(min/bw)*bw`) before the Gaussian fit; on the reference Octahedron tracking file this gives ≈ **0.6375**, matching the MATLAB scripts (≈ 0.637497). Detailed variants `estimate_size_nd_details()` / `estimate_anisotropy_details()` exist alongside the original public APIs.
- **`estimate_size_nd_details` groups by id with a single stable sort** (argsort → contiguous-block walk), **not** a per-id `ids == cid` mask. The old mask was O(N × n_traces) and, on files with ~10 k traces × ~270 k locs, made dataset open hang ~20 s (it runs 4×: x/y/z + z-corrected). Same fix in `localization_precision.py::stddev_per_trace`. Both are verified to give bit-identical results to the masked version (`tests/test_post_load.py`). Keep the sort-based grouping.
- **Auto-RIMF-on-load + post-load chain** (`main_window._run_post_load_computations` → `_post_load_rimf`/`_post_load_rimf_estimate`/`_post_load_loc_prec`/`_post_load_density`/`_post_load_finalize`): RIMF 2D → 1.0; `use_fixed_rimf` pref → fixed value; else estimate from raw — outside `[0.5, 1.0]` is treated as failed and reset to 1.0; then `state.notify_calibration_changed(idx)`. The steps are **chained via `QTimer.singleShot(0)`** (`_post_load_next`) so each returns to the event loop — the Log shows live per-step progress (with timings) and the UI stays responsive instead of freezing through the whole batch. Each step **re-resolves the dataset by identity** (`_post_load_index`) so closing it mid-chain (or removing another dataset, which shifts indices) aborts/retargets safely. The heavy RIMF estimate is announced (logged) one turn before it runs so the message paints first.
- **Apply-to-data refresh.** The anisotropy dialog has an editable RIMF spinbox (defaults to the computed value) + **"Apply to data"** which calls `ds.set_rimf(value, source="manual (anisotropy plugin)")` then `state.notify_calibration_changed(idx)`. `AppState.calibration_changed` is wired to: render (re-pull `loc_nm`, re-render, refresh volume), scatter (invalidate its loc cache keyed by dataset index — otherwise stale z — then redraw), and the Data window (refresh the RIMF text). A plain XY render won't visibly change (RIMF only scales z); the effect shows in 3-D/volume, scatter XZ/YZ/3-D, and the Data window.
- **Wording convention.** The dialog headline reads **"anisotropy factor = <value> (Gaussian fit)"** (the measured `geomean(size_x,size_y)/size_z`, depth-dependent, not strictly one z-scale); the overlay panel adds an orange dash-dot `Z' = geomean(X,Y)` line; everywhere else the abbreviation is **"RIMF"** (always upper-case — Refractive Index Mismatch Factor). The Data window shows `RIMF = <value> (<source label>)` (calculated → 4 decimals; manual/fixed/1.0 → 2 decimals). Don't reintroduce lower-case "rimf" in user-facing strings; code identifiers (`cali.RIMF`, `metadata["rimf_provenance"]`, `result["rimf"]`) stay as-is.

## Window modality / ownership
**Analysis result windows and plugin windows are modeless and non-owned by default** — they must not block the app or sit permanently in front of viewers. Build them with **no QWidget parent** (`super().__init__(None)`) and show them via `ui/modeless.py::show_modeless(window, owner)`, which sets non-modal + `WA_DeleteOnClose` and retains a reference in `owner._modeless_windows`. Pass the main window only as the *owner* (lifetime + main-window lookups via a stored `self._owner`), never as the QWidget parent — a parented top-level window with the `Qt.Window` flag is an *owned* window the OS pins above its owner (this was the MSR reader's "always in front" bug). Because they are non-owned they do NOT auto-close with the main window, so `MainWindow._close_all_child_windows()` calls `modeless.close_modeless(self)` on shutdown; drain any new modeless registry there too. Use a **modal** dialog (`.exec()`) only when the caller needs a decision/value before continuing (alignment/field/parameter pickers, file dialogs, `QMessageBox`, Preferences). The Dataset Manager is also a non-owned top-level window (kept alive via `MainWindow._ds_manager`, owner stored as `self._owner`) — it must NOT use `WindowStaysOnTopHint` or a QWidget parent. The Brightness/Contrast palette is a window **owned by its opener** (render / TIFF / segmentation window passes `parent=self`), so it floats above its owner in z-order and gets no taskbar/Dock button — without `WindowStaysOnTopHint` (a `WS_EX_TOPMOST` window is shown on *every* Windows virtual desktop and follows you across desktops). Its window type is **platform-gated**: on **Windows it is NOT a `Qt.Tool` window** — `Qt.Tool` sets `WS_EX_TOOLWINDOW`, and a tool window is *also* shown on every virtual desktop (documented Windows behavior for tool windows, independent of `WS_EX_TOPMOST`); a plain **owned dialog** is instead bound to the desktop it was created on and only moves when the user drags it there. On **macOS/Linux** it keeps `Qt.Tool` (the thin utility-palette look, no multi-desktop issue). The gate lives in `BrightnessContrastDialog.__init__` (`sys.platform.startswith("win")`). `show_modeless` works for **any top-level `QWidget`**, not just `QDialog`: it guards the `QDialog`-only `setModal` (`isinstance(window, QDialog)`) and relies on `setWindowModality(NonModal)` for plain widgets — calling `setModal` unconditionally raised `AttributeError` and silently left the window unshown/unregistered, which is why the **Local Density result window** (`analysis/local_density.py::LocalDensityImageWindow`, a `QWidget`) leaked past main-window shutdown (`tests/test_local_density_window.py`).

### Opening a file the OS hands us (argv + macOS Open-Document)
`MainWindow.open_path_from_desktop(path, *, source)` is the **single entry point** for "the OS asked us to open this" — it logs `Open request (<source>, pid <n>): '<name>'`, raises/activates the window, then calls `_route_path` (so folders and `.zarr` stores work like a drop). Two routes feed it:
- **Command line** (all platforms): `startup_paths_from_argv(sys.argv[1:])` in `main_window.py` — accepts every entry in `_SUPPORTED_EXTS` **plus directories**, and drops option-like args, notably the **`-psn_0_…` process-serial-number argument macOS passes to a bundled `.app`**. (The old inline loop in `__main__` accepted only `.mat/.npy/.csv/.msr` and used `_route_file`, so `.json`/`.tif`/`.zarr` and folders were silently ignored.)
- **macOS Open-Document event**: `ui/file_open_app.py::FileOpenApplication` (a `QApplication` subclass, installed on every platform, inert off macOS). **macOS never puts a dropped/double-clicked document in `argv`** — Launch Services sends the running process an `kAEOpenDocuments` ("odoc") Apple Event, which Qt turns into `QFileOpenEvent`. The event can arrive **before `MainWindow` exists** (during `QApplication` construction, on a cold launch-with-document), so paths are **queued** until `set_open_handler()` is called after the window is built, then flushed in order. A handler exception is caught — it would otherwise cross the C++ boundary out of `QApplication.event()`.

**All three layers are required; none is sufficient alone.** The bundle must also declare `CFBundleDocumentTypes` in `minflux_viewer.spec`'s `BUNDLE(info_plist=…)`, or Launch Services has no registered running-instance handler for e.g. `.msr` and **launches a second copy of the app** instead of delivering the document (the reported "dropping a `.msr` on the app icon opens a new instance" bug). `LSHandlerRank` is **`Alternate`**, not `Owner` — Imspector owns `.msr` where installed and we must not steal the association. `.zarr` needs its **own entry with `LSTypeIsPackage: True`** (it is a directory, so Finder would otherwise open it as a folder); everything else sets it `False`. `LSMultipleInstancesProhibited: True` asks for one instance.

**`ui/single_instance.py::SingleInstanceGuard` is the layer that does not depend on macOS.** The plist keys are declarations Launch Services may ignore in practice — its database caches bundle metadata (a copy registered before the keys existed keeps the old registration), several copies of one bundle id on disk (`dist/`, an extracted zip, `/Applications`) are separate registrations so a document can go to a *different copy than the running one*, and an unsigned/quarantined/relocated bundle is not always treated as a registered app. The guard sidesteps all of it: the first process listens on a per-user `QLocalServer`; a later process **hands its paths over and returns exit code 0 without building any UI** (`hand_off_to_primary` → `return 0` in `__main__`). Opt out with `MINFLUX_VIEWER_ALLOW_MULTIPLE=1`.
- Transport details that are load-bearing: the sender **waits for the primary to close the connection** (`waitForDisconnected`) rather than disconnecting itself — an immediate client-side disconnect drops the bytes before the peer accepts, on Windows named pipes outright. `_consume` therefore calls `disconnectFromServer()` **whether or not the request parsed**, or a malformed hand-off leaves the sender blocked until its timeout. The server drains on `readyRead`, on `disconnected`, **and once immediately on accept** (the sender may already have written and closed).
- `listen()` calls `removeServer` and retries once, so a socket left by a crashed run does not permanently block startup; it is only reached after `hand_off_to_primary` found no live primary, so it cannot disconnect a running instance. `app.aboutToQuit → guard.stop()` refuses hand-offs during shutdown, so a newcomer becomes the primary rather than handing files to a dying process.
- **`hand_off_to_primary` blocks in `waitFor*`, which does not pump the primary's event loop — so a same-process "second launch" deadlocks against the server it is calling.** `tests/test_single_instance.py` spawns a **real subprocess** for the sender; do not "simplify" it back to one process.
- `PyQt6.QtNetwork` is in the spec's `hidden_imports`: losing it does not degrade a feature, it stops the app booting.
- **`scripts/check_macos_bundle.py <app>`** diagnoses a built bundle read-only: whether the fix is actually inside it (greps the packed PYZ, so a stale build is obvious), whether the plist keys landed, and whether `mdfind` finds other copies sharing the bundle id (with the `lsregister -kill -r` command to refresh the database).

Diagnosing which instance handled a drop is otherwise near-impossible — both processes share one Dock icon and analysis windows are non-owned top-levels, so the window that appears is **not** evidence of the process that opened it. The `pid` + `source` in the log line is. Regression: `tests/test_file_open_events.py` (argv filtering, odoc queueing/dispatch, and the plist parsed out of the spec).

### Shutdown / platform cleanup
`minflux_viewer.__main__.main()` returns an integer exit code and the `if __name__ == "__main__"` block calls `sys.exit(main())`; do not put `sys.exit(app.exec())` back inside `main()`. After `app.exec()` returns, the code calls `window.deleteLater()`, `app.processEvents()`, and restores Console redirection so Qt/Python teardown happens cleanly, especially on macOS app bundles. `MainWindow.closeEvent` sets `_is_shutting_down`, closes owned/modeless windows, cancels/disconnects pending update-check `QRunnable`s, clears the global `QThreadPool`, and waits briefly (`_drain_background_tasks`) before restoring stdout/stderr. This fixed macOS "Python/MINFLUX Viewer quit unexpectedly" dialogs on normal quit. Any new delayed `QTimer.singleShot`, `QRunnable`, `QThread`, or modeless registry must be guarded/drained in the same shutdown path. For monospace UI widgets use `QFontDatabase.systemFont(QFontDatabase.SystemFont.FixedFont)`; do not hard-code Windows fonts such as Consolas (macOS logs missing-font alias warnings and pays a startup cost).

## Viewer rules
Viewer families: render, scatter, histogram, attribute plot, trace viewer, 3-D volume preview.

- Each normal plot window (render, scatter, histogram, attribute, filter dialog) is **dataset-owned**: one window per dataset, reused. Opening for a different dataset must not swap content inside an existing window. Focusing a window sets that dataset active.
- `_show_scatter/histogram/attr_plot/render` guard against `QAction.triggered`'s `checked=False` (a bool) with `type(x) is int` — not `isinstance` or `is not None`.
- Overlay: datasets stay separate; layers combined only at the viewer. Overlay keys in `dataset.state`: `overlay_id`, `overlay_order`, `overlay_lut`, `overlay_transform`, plus compat keys `render_group_id` / `render_transform_2d`. Helpers: `core/overlay.py`. Overlay transforms are 4×4 homogeneous display matrices applied at render/scatter time; raw localization attributes must not be modified.
- **Combining in place must fold the members' coordinate views.** *Process › Channel… › Combine* with **keep source dataset unchecked** turns the selected datasets into overlay channels **in place** — no dataset is added or removed, so each member's already-open render/scatter window survives, keyed by its own index and still drawing/titling it as a standalone dataset. Render and scatter are overlay-aware (one window keyed by the **anchor** draws every channel), so those leftovers are stale duplicates — the reported "one dataset always stays in its own view". `main_window._collapse_member_coordinate_views(member_indices, anchor_idx)` closes and de-registers them, returning whether any member had a **scatter** so `_show_channel_combine` can reopen it on the anchor (otherwise folding would leave the user with no scatter at all). Only `_render_windows`/`_scatter_windows` are folded: a histogram / attribute plot / data window of one channel is still meaningful. The **keep-source** path is unaffected — the overlay is built from fresh duplicates whose indices have no windows, so the call is a no-op there and the originals stay standalone. Regression: `tests/test_channel_combine_views.py`.
- **An `overlay_id` alone does NOT make a dataset an overlay** — it is only a grouping hint, and the MSR import assigns it *before* it knows how many channels will succeed. Membership is `core/overlay.py::is_multichannel_overlay(state, idx)` = has a group id **and** `len(overlay_members(...)) > 1` (`overlay_members` includes the anchor, hence `> 1`). `main_window.dataset_view_status` used `any(other.overlay_id == group_id for other in datasets)`, which is trivially true for the dataset itself, so a **single-channel `.msr` import always displayed as "Overlay" instead of "Own"** in the Dataset Manager. Belt-and-braces: a one-dataset import now calls `overlay.clear_overlay_assignment(ds)` (drops `overlay_id`/`render_group_id`/`overlay_index`/`overlay_order`/`overlay_lut`/`render_channel_lut`/`overlay_transform`/`render_transform_2d` from `state`, and the `overlay_*`/`transformed` keys from `metadata`) so the provisional grouping never survives. Regression: `tests/test_overlay_membership.py`.
- Render manual channel alignment is temporary while the modal keyboard dialog is open, but **Apply** composes the manual translation/rotation into the dataset's stored `overlay_transform`/`render_transform_2d` as a full 4×4 matrix (stable across pan/zoom/re-render). Plane semantics: XY translates X/Y and rotates about Z; XZ translates X/Z and rotates in XZ; YZ translates Y/Z and rotates in YZ. The tile-warp preview clamps invalid/negative/interpolation-dust pixels.
- Channel rows in overlay panels use `QLabel` (not `QCheckBox`) for the name so mouse clicks propagate to `mousePressEvent` → active-dataset switch.
- **Scatter colormap** (`scatter_window.py`): named LUTs are `glasbey`, `jet`, `HiLo`, `parula`, `turbo`, `hot`. **Solid colors** are encoded as `solid:<Name>` (Red/Green/Blue/Cyan/Magenta/Yellow/Black/White/Gray) or `solid:custom:#rrggbb`; `_load_cmap` builds a flat 2-stop colormap and `_update_colorbar_visibility` hides the colorbar in solid/overlay/3-D modes. The `_cmap_combo` is editable so these string values round-trip. The old `(density)` colour-by option was removed (`den` supersedes it; `fast_density_2d/3d` kept in `utils/filters.py` but unused).
- **Scatter loc cache** is keyed only by dataset index — invalidate it (`_cached_locs_nm = None`) on `calibration_changed`, or RIMF changes show stale z.
- **XY origin / Y-axis direction** is a per-viewer preference (`plot.render_xy_origin` / `plot.scatter_xy_origin`, default `"top_left"`): `top_left` = Y increases downward (ImageJ/MATLAB image convention), `bottom_left` = Y increases upward. Each window applies it via `_apply_y_axis_direction()` (`ViewBox.invertY`) and exposes `refresh_preferences()`, which `main_window._refresh_plot_preferences()` broadcasts to all render+scatter windows after Preferences OK. **Render** inverts Y in image mode whenever top-left, and in localization mode **only in the XY orientation** (`_should_invert_y_axis`); XZ/YZ keep natural Y. **Scatter** inverts only when its axis combo is `XY`. Both are set on the **2-D `ViewBox` only** — the 3-D scatter mode is unaffected. Appearance preferences expose a "Display XY coordinates as" combo under both Render View and Scatter Plot (`_XY_ORIGIN_OPTIONS`).
- **Scatter 3-D reference items.** In 3-D mode the scatter window draws a toggleable OpenGL **axis** (with `_tick_values`/`_fmt_tick` numeric tick labels via `GLText`) + **bounding box** + **grid**, built by `_refresh_3d_reference_items` / `_draw_3d_axis` / `_draw_3d_bounding_box` / `_configure_3d_grid` over `_visible_xyz_3d` (visible, filtered, RIMF-scaled locs). Visibility is persisted per window (`show_3d_axis` / `show_3d_bounding_box`, both default True); `_set_3d_axis_visible` / `_set_3d_bounding_box_visible` toggle them. Colours come from `_reference_color()` / `_text_color()`.

## ROI system
- `core/roi.py` / `core/roi_selection.py` / `ui/roi_overlay.py` / `ui/roi_manager.py` are the shared ROI plumbing. Attribute Plot rectangular ROI selection stores masks in `dataset.derived[...]` and metadata in `dataset.state["roi_masks"]`; masks align to the materialized rows used by the current plot. `AppState.roi_selection_changed` notifies other windows.
- ROI masks are selection/highlight overlays, **not** filters. Do not mutate raw arrays or `filter_mask` when drawing/selecting an ROI.
- Scatter and render windows highlight the active draft ROI and selected ROI-Manager entries using each ROI's own `stroke_color` (do not hard-code the old gold overlay). Render highlights use transformed/display coordinates, current XY/XZ/YZ orientation, channel visibility, active filters, depth range, overlay transforms. TIFF/image-only render mode has no localization rows, so ROI localization highlighting is cleared there.
- **ROI-set I/O & ImageJ export.** Native ROI-set JSON is `{"version":1,"rois":[…]}` (`is_roi_json_file` detects it: a dict with a `"rois"` list). Such files — plus ImageJ `.roi`/RoiSet `.zip` — load into the **ROI Manager** by drag-and-drop on **both** the main window (`_route_file`: `.roi`/`.zip` → `_load_roi_json`; `.json` → `_load_json` which checks `is_roi_json_file` first) and the **ROI Manager dialog** itself (`setAcceptDrops` + `dropEvent` → `_load_roi_path`); loaded ROIs are retargeted to the active dataset, selected and Show-all'd. ImageJ `.roi`/`.zip` export is **no longer blocked** for plot/attribute-coordinate ROIs: `record_to_imagej` writes the nm geometry **directly as ImageJ pixel coordinates** (spatial calibration lost — matches a 1 nm/pixel viewer TIFF export; use native JSON for an exact, calibrated round-trip); a **rotated** rectangle/oval is exported as a **polygon** (`_rotated_outline_points`) so the rotation survives. The "coordinates written as pixels" notice goes to the **Log**, not a blocking dialog (`roi_manager._save`).
- **ROI types** (`ROI_TYPES` in `core/roi.py`): `rectangle`, `oval`, `polygon`, `freehand`, `line`, `polyline`, `freehand_line`, `magnetic_lasso`, `point`, `angle`. `line`/`polyline`/`freehand_line`/`magnetic_lasso` are **open-line** ROIs (`OPEN_LINE_TYPES`) — no enclosed area. Toolbar order/buttons live in `main_window.py::_ROI_TOOL_DEFS` + `toolAngle`; the **Line**, **Rectangle**, and **Oval** toolbar buttons each carry a right-click family switcher (Fiji-style — Line → straight/poly/freehand line via `_LINE_FAMILY`; Rectangle → axis-aligned/rotated via `_RECT_FAMILY`; Oval → axis-aligned/ellipse via `_OVAL_FAMILY`), wired in `_install_roi_tool_menus` via an **event filter** (not `customContextMenuRequested`, which a QToolButton-in-QToolBar swallows). `set_tool` gates on **`ROI_TOOLS`** (= `ROI_TYPES` ∪ `{rotated_rectangle, ellipse}`); the variant tools are valid *tools* but **never** record *types* (see the rotated-variant bullet).
- **Line-direction end marker.** Open-line ROIs have a **direction** (begin → end, which Plot Profile follows), so `_make_item` restyles the **last** vertex handle of `line`/`polyline`/`freehand_line` as a round **oval** so the end reads distinctly from the square start / intermediate vertices. `_mark_line_end_handle(item)` does this **in place**: it swaps the handle's local `path` to an ellipse (`QPainterPath.addEllipse`) at the **same radius** as the square start handle (only the *shape* differs — not enlarged), sets `_is_line_end_marker=True`, and resets the shape cache — the handle stays an ordinary draggable free handle (`typ='f'`, performs **no** rotation) and its **sip/C++ type is left untouched**. ⚠️ **Never reassign `handle.__class__`** on a pyqtgraph `Handle` (an earlier `__class__`-swap to a filled-oval subclass **crashed the app** under the rapid create/destroy churn of a live draft drag — the sip object's type must not change). Works for both `LineSegmentROI` and `PolyLineROI`, and applies to the **angle** ROI too (its end/`C` corner is rounded, apex `B` + start `A` stay square). Skipped only for a **closed** loop (region→Line outline). Re-applied on every `_make_item` rebuild; 3-D lines are the same item (projected to the plane), so they're covered too. Regression: `tests/test_line_end_marker.py`.
- **Accumulating tools** (polygon / polyline / `magnetic_lasso` / angle): every left-click registers a vertex — even when the click lands over the in-progress draft — so the vertex branch runs **before** the `_record_at` hit-test gate. Right-click finishes the shape **and** releases the toolbar button (`_finish_polyline`/`_finish_lasso` always call `_maybe_release_tool`). The **magnetic lasso** snaps each click to the local density centroid of the render raster (`core/magnetic_snap.py::snap_density_centroid`, exposed via the owner's `snap_to_density`).
- **Enclosed-region masks for all shapes.** `roi_selection.py::roi_region_mask(x, y, record, base_mask=)` dispatches rectangle/oval/polygon/freehand → boolean masks (line/point → all-False, no area). Polygon/freehand use the **even-odd (PNPOLY) rule** (`_point_in_polygon`) so a self-intersecting "figure-8" encloses **both** lobes (matplotlib's nonzero winding drops one). Oval/polygon/freehand drafts get a translucent fill + data highlight like rectangles (`FilledRectROI`/`FilledEllipseROI`/`FilledPolyLineROI` in `roi_overlay.py`). `render_window`/`scatter_window`'s `compute_roi_selection` only build masks for `{rectangle, oval, polygon, freehand}`.
- **Explicit add-to-Manager.** A drawn ROI is **not** in the store until the user adds it: shapes/line/angle persist a single `draft` (added via ROI Manager *Add* or right-click *Add to Manager*); points persist as **session points** (`_session_points`/`_session_items`, multiple, drawn but not in store). Right-clicking a session point offers *Add to Manager* (that point) and *Add all session points to Manager* (the whole pending set). `consume_draft`/`_commit_point` route through `_normalize_record` so depth/plane context is stamped on persist.
- **Point ROI = fixed-size 3-D marker.** `PointMarkerItem(pg.TargetItem)` paints translucent concentric jet rings (ilastik density-count look), **constant pixel size regardless of zoom**, draggable. The point tool is **multi-shot**: the toolbar button stays pressed (no auto-release) until clicked again. Geometry is a full XYZ `{"point":[x,y,z]}` — see 3-D placement below. ImageJ export is a native `ROI_TYPE.POINT` per record (not polygon vertices); plot-coord points save to native JSON only.
- **Drawn-ROI 3-D placement.** A ROI drawn in a 2-D view gets a real out-of-plane (depth) value, not a leftover in-plane coordinate (the old bug where a point's "Z" read as the ~2×10⁴ nm Y value). The depth is **data-aware**: `roi_depths_at(points)` returns the XY-proximity-weighted median depth of the localizations near each vertex (`core/roi_depth.py::weighted_depths`, KD-tree/brute-force) so a vertex snaps onto the structure under it; it falls back to `roi_depth_center()` when the XY column is empty. Owners expose `roi_view_plane()` (XY/XZ/YZ) + `roi_depth_center()` (render = depth-slider midpoint; scatter = data extent of the off-axis) + `roi_depths_at(points)` + `normalize_roi_record()` (stamps `view_plane`/`depth_axis`/`depth_value` in `record.context`; non-point shapes keep 2-D geometry + this metadata). Points carry full XYZ and **project** to each view via `roi_overlay.py::project_point` / `point_to_3d` / `update_point_in_plane` (drag in XZ/YZ edits Z, preserving the untouched axis); `refresh()` re-projects markers when the view plane flips. **Any code reading a point geometry must be 3-D-safe** — index `pt[0]`/`pt[1]`, never `x, y = pt`.
- **Line geometry must stay dimension-homogeneous.** `_open_line_geometry_from_item` preserves each vertex's depth by 1:1 index pairing (`update_points_in_plane`) **only when the vertex count is unchanged**; on a **count change** (pyqtgraph's `PolyLineROI` adds a vertex when you click a segment — easy to hit clicking near a wiggly freehand line — or a delete) the index pairing is invalid, so it **re-derives a consistent 3-D geometry** from the item's 2-D vertices via `_points_to_3d` (data-aware depth). Before this, an added vertex was appended as a **2-D** point next to the existing **3-D** ones, and `np.asarray(points)` in `_bounds`/`record_to_points` then raised `ValueError: inhomogeneous shape (N,) + inhomogeneous part` (crashed drawing / arrow-moving a freehand line). Defence-in-depth: `_bounds` (both `ui/roi_overlay.py` and `core/roi.py`) and `core/roi.py::record_to_points` build the `(x,y)` array per-vertex (`np.array([[p[0],p[1]] for p in raw])`) so they tolerate a transient 2-D/3-D mix. Regression: `tests/test_open_line_roi.py`, `tests/test_line_end_marker.py::test_vertex_add_keeps_line_geometry_homogeneous`.
- **Angle ROI** (ImageJ-style): three clicks A·B·C → angle ABC in `[0, 180]` via `roi_overlay.py::_angle_abc`; reported live to the status bar (falls back to the Log). Drawn with a `PolyLineROI`; not a region (no mask).
- **Live draw/edit read-out (status bar).** Every draft update surfaces a concise geometry line to the main-window status bar via `roi_overlay.py::_report_roi_status` → `_emit_status` (`owner._state.status_message`): `_set_draft` reports on every live draw (rubber-band drag, polygon/polyline vertex add), and `_connect_draft_edit` wires `sigRegionChanged`/`sigPositionChanged` → `_report_status_from_item` for live edits. `_roi_status_text(roi_type, geometry)` is a pure static formatter (integer nm, 3-D-safe point indexing): rectangle/oval `X=…, Y=…, W=…, H=… (+ , angle=…°)`; a **straight `line`** reports its start vertex + length + direction `Line N vertices, X=…, Y=…, length=…, angle=…°` (angle = `atan2(dy, dx)` from the +X axis, one decimal, in `(-180, 180]`, start treated as the polar origin); other multi-vertex shapes `<Type>  N vertices  Bounding Box X=…, Y=…, W=…, H=…`; point `X=…, Y=…`. Session-point placement (`_commit_point`) reports `Point X=…, Y=…  (session point N)`. **Angle keeps its dedicated `_report_angle`** read-out (`_roi_status_text`/`_report_roi_status` skip `angle`). The read-out **clears** (`_clear_status` → blank) when the draft is deleted/cancelled/committed (`_clear_draft`) or any ROI is deleted (`_delete_hit_roi`), so a stale geometry doesn't linger after the ROI is gone. Regression: `tests/test_status_progress.py::test_roi_status_readout_text`.
- **ROI naming & properties.** `RoiRecord.create`'s default name is `""`; `RoiStore.add` assigns a **1-based** `<type>-<n>` (`next_type_index`), treating empty or legacy `<type>-<4hex>` names as auto (`_is_auto_name`). The ROI Properties dialog (`roi_overlay.py::_show_roi_properties`) is a **selectable-text** `QMessageBox` with monospace geometry in **integer nm** (`_fmt`, e.g. `X=12000, Y=21001, W=331, H=414`) for all types; **rectangle and oval also show `angle=…°`** when rotated. "Localizations within" appears only for region types. **Add to Manager** removes the drawn shape from the view (it now lives in the store); **Show all** faithfully hides/shows every ROI including points.
- **Rotated rectangle/oval geometry invariant.** `geometry["bounds"]` is the ***unrotated*, centre-consistent** axis-aligned box `[x, y, w, h]` (its centre `(x+w/2, y+h/2)` is the rotation centre) plus `geometry["angle"]` (degrees, CCW). pyqtgraph rotates a ROI about its *origin*, so `_make_item` offsets the ROI origin by `−R(angle)·(w/2,h/2)` and `item_to_geometry` reads the true centre via `item.mapToParent(w/2,h/2)` — for **both** rectangle and oval (the oval previously dropped its angle → "snapped back"). Because bounds is centre-consistent, `roi_selection.rectangle_mask`/`oval_mask` and the `_point_hits_record` hit-test (rotate the query point about the centre) are correct after rotation. Line/polyline vertices may be 3-D (carry a depth); `core/roi._bounds` slices to `[:, :2]`.
- **Rotated-rectangle & ellipse tools (ImageJ-style variants).** The **Rectangle** and **Oval** toolbar buttons each host a right-click Fiji-style family switcher (`_RECT_FAMILY`/`_OVAL_FAMILY`, structured like `_LINE_FAMILY`) with tools `rotated_rectangle` / `ellipse`. **These are drawing-*tool* names only — the record `type` stays `rectangle`/`oval`** (so masks, hit-tests, save/load, ImageJ export, conversions, crop are all unchanged); `geometry["variant"]="rotated"` is the sole marker, and it drives **only the handle layout**. A rotated variant is geometrically just a rect/oval with `geometry["angle"]≠0` (rotation was already fully supported). Drawing gesture (`_update_drag_draft` → `roi_overlay.center_axis_box`): the click-drag P0→P1 is the **long centre axis** (its length + direction set length + rotation); the perpendicular side = `GOLDEN_MINOR` (≈0.618) × length, centred on the axis (so the box centre = the drag midpoint = the rotation centre). Handle layout (`_add_rotated_variant_handles`, fracs from `rotated_variant_handles(roi_type)`): **4 handles** — one **`SolidSquareHandle`** pivot (a rotate handle about `[0.5,0.5]`, so **dragging the solid corner rotates about the centre**) + 3 `SquareHandle` scale handles. **Both variants put all four at the edge midpoints / axis endpoints (Fiji-style)**: pivot = `(0,0.5)` = the drawing-origin edge middle (the click point = `center_axis_box`'s P0), scale handles = `(1,0.5)` (opposite edge middle = drag end) + `(0.5,0)`/`(0.5,1)` (the two perpendicular edge middles). (`_ROTATED_RECT_HANDLES` == `_ROTATED_OVAL_HANDLES`.) Arrow keys: `_rect_handle_role_at` is variant-aware (pivot frac → `"rotate"`; the plain layout has **no** rotate role), so selecting the pivot + arrow rotates 1°/press, and the scale handles resize as usual. **Angle read-out is wrapped to (-180, 180]** by `roi_overlay.normalize_angle_deg` in `item_to_geometry` (+ the status/property formatters): a pyqtgraph rotate handle accumulates the raw `item.angle()` across full turns, so an ellipse spun several times reported e.g. `-7140°` before this (rotation is periodic mod 360, so the wrap is display/storage only — masks are unchanged). **Variant preservation:** `item_to_geometry(roi_type, item, prev=geometry)` copies `variant` across a re-read (item geometry alone can't distinguish it) — passed at both geometry-committing call sites (`_update_draft_from_item`, `record_for_update`); `normalize_roi_record` (render/scatter) only touches `context`, so the store commit keeps it. **Icons** reuse the base `rec.png`/`ellipse.png` turned 45° at runtime (`_rotated_icon` via `QPixmap.transformed`, no new asset). Regression: `tests/test_roi_keyboard.py` (`test_center_axis_box_*`, `test_rotated_variant_*`, `test_draw_rotated_rectangle_*`, `test_draw_ellipse_*`, `test_item_to_geometry_preserves_variant_marker`).
- **Stored ROIs are live-edit copies; the Manager record changes only on Update.** `_connect_edit` does **not** auto-commit view edits to the store (only the angle ROI's live status read-out is wired). Moving/reshaping a displayed stored ROI leaves its `RoiStore` record (and cached highlight) unchanged; the Manager **Update** calls `record_for_update` which reads the item geometry (`item_to_geometry` reads multi-vertex handles in **scene→parent** coords, so a body *move* — not just vertex edits — is captured) and commits + re-queues the selection mask.
- **`refresh` rebuilds a displayed item when its store record is *replaced*.** Convert / Resize / Skeletonize / vertex-edit on a **stored** ROI do `store.update(id, new_record)` (a *new* record object, possibly a different type). `RoiOverlayController` tracks `self._item_records[id]` = the record object each live item was built from; `refresh` rebuilds the item when `_item_records[id] is not record` (identity check — O(1), popped on removal). A **live drag** does *not* rebuild: the record object is unchanged during an uncommitted edit, so the identity still matches and the dragged item is preserved. ## Render pipeline
| File | Role |
|------|------|
| `ui/render_window.py` | Main widget, UI, dispatch |
| `ui/render_config.py` | All tunable constants |
| `core/spatial_grid.py` | O(k) bounding-box index |
| `ui/tile_cache.py` | LRU cache + `TileKey` |

Two paths — threshold `DIRECT_RENDER_THRESHOLD_NM = 20 nm/px`:
- **Tiled** (≥ 20 nm/px): LOD 0 (≥ 100 nm/px, 50 px tiles) and LOD 1 (20–100 nm/px, 100 px tiles). Async workers; generation counter discards stale results.
- **Direct** (< 20 nm/px): bypasses tile cache, renders at exact viewport resolution. Sparse (< 500 locs): per-localization Gaussian. Dense: `histogram2d`.

Key constraints:
- **`_on_filter_changed` must call `_refresh_depth_state()`, not `_apply_orientation()`** — the latter resets the viewport via `_fit_view()`. Filter toggles must not move pan/zoom.
- **Zoom-out limit (`_ZOOM_OUT_LIMIT = 2.0`) is enforced in `_on_range_changed()`, not via `ViewBox.setLimits`** — `setLimits` causes cursor drift.
- **Initial fit is re-run once on first show (`showEvent` → `QTimer.singleShot(0, _fit_view_on_first_show)`, guarded by `_did_initial_fit`).** The construction-time `_fit_view()` runs before the window is on screen, so the `ViewBox` reports a placeholder pixel size; PyQtGraph's aspect-lock re-enforcement on the first real resize then **clips the X extent of a wide dataset** (full height shown, left/right cut off — reproduced on a 16 µm × 6 µm file in the ~square 880×920 default window: view settled to `vW≈9974 < 14758` data width). The deferred re-fit at the real on-screen size restores full coverage. The `_did_initial_fit` guard makes it one-shot, so re-raising an existing render window (`_show_render`) does **not** reset the user's zoom/pan. Inherited by `PrecisionRenderWindow`. Regression: `tests/test_render_fit_view.py`.
- `TileKey` has 8 fields including `depth_range`; omitting any causes `TypeError` at first render.
- Safety caps: `_MAX_CANVAS_PX = 3000`, `_MAX_TILES_PER_AXIS = 64`. Auto Gaussian sigma = `pixel_size_nm × 0.5`; skipped when `sigma_px < 0.3`.
- **Render Mode switch (basic ↔ advanced).** Every render window's right-click menu has a **Render Mode** submenu (`_RENDER_MODE_INFO` + `RenderWindow.RENDER_MODE`, `PrecisionRenderWindow.RENDER_MODE="advanced"`) with checkable **Basic**/**Advanced** items (`menu.setToolTipsVisible(True)` → per-item hover help explaining the mode + its reconstruction). Picking the other mode calls `RenderWindow._switch_render_mode` → `main_window._swap_render_mode(win, mode)`, which **swaps the window in place**: captures orientation + view range + geometry, drops the old window from its registry (`_render_windows` / `_advanced_render_windows`) and closes it, opens the other engine via `_show_render`/`_show_advanced_render` for the same dataset, and restores geometry/orientation/zoom — plus the **active ROI draft is re-applied** on the new engine (`_swap_render_mode` captures `win._roi_overlay.current_record()`, deep-copies it, and `replace_draft`s it on the new window via a deferred `QTimer.singleShot`) so a drawn-but-unsaved ROI survives the swap. So exactly one render window (one engine) exists per dataset at a time. Advanced is disabled in image mode. The **Render Mode submenu lives inside the right-click `View` submenu, directly below `White background`** (not top-level); `_RENDER_MODE_INFO` tooltips are hand-wrapped to short lines so the hover help reads as a compact block. Naming: the engine is the **Mode** (Basic/Advanced); the reconstruction picker inside advanced is the **Method** (histogram/Gaussian) — the advanced help item/dialog is "Render Methods…" / "Advanced Rendering Methods" (was "Render model..."/"…Models"). - **Advanced 2-D render view** (`ui/precision_render_window.py::PrecisionRenderWindow`), kept in a separate main-window registry (`_advanced_render_windows`) from the production renderer. **Reached via the render window's right-click View › Render Mode › Advanced switch — the standalone `View > Render View (advanced)` menu entry / `actionRenderAdvanced` was removed** (`_show_advanced_render` stays; only the mode swap and the swap-back open/close it). It reuses all normal render interactions/compositing. **Renderer** combo (default = **Localization-precision Gaussian**, at the top): `Localization-precision Gaussian`, `Histogram`, `Bilinear histogram`, `Bicubic histogram`, `Basic (smoothed histogram)`, `Fixed Gaussian`. (The old redundant `Automatic` alias was **removed** — `RENDER_METHOD_AUTOMATIC` is gone.) Each item carries a **per-item hover tooltip** (`_RENDER_METHOD_TIPS`, set via `setItemData(i, tip, ToolTipRole)`) so scrolling the open dropdown explains each method. Pure scalar reconstruction functions and its dedicated async scheduler live in `ui/precision_render.py`. Every localization has unit weight; bilinear splits one count over the 4 nearest pixel centres; **bicubic** (`render_bicubic_histogram`) splits it over a 4×4 Catmull-Rom neighbourhood (smoother sub-pixel, ~2× bilinear, clamped ≥0 to drop the kernel's negative lobes); precision Gaussian uses transformed anisotropic X/Y/Z marginals with source priority per-localization → per-trace StdDev → dataset calibration → reported 5 nm fallback. **`Basic` and `Fixed Gaussian` use `render_gaussian_filtered` (histogram → separable `scipy.ndimage.gaussian_filter` on a halo-padded grid, cropped seamlessly)** — O(pixels), *independent of localization count and of sigma*, ~100–1600× faster than stamping a pixel-integrated Gaussian per localization (which costs O(N·(4σ/px)²) and blows up when zoomed in / at large sigma). `Basic` = the production "smoothed histogram" look (½-pixel anti-alias blur that scales with zoom); `Fixed Gaussian` = one user `sigma` (default `_DEFAULT_SIGMA_NM=5 nm`, the reported-precision fallback) for every localization. Only the **precision** method (per-loc variable sigma) still needs `render_precision_gaussians` (a single global blur can't cover many sigmas — a future sigma-binned histogram+blur could speed it too). **One consistent tile path at every zoom** — the separate production-style overview was **removed** (no `_show_overview`/`_is_overview_bounds`/`_overview_*`/`_render_state_key`); the default (precision Gaussian) renders at all zooms, tile resolution adapting to the view; at extreme zoom-out the sub-pixel footprints degenerate to a fast histogram, so no separate overview is needed for speed. Explicit methods stay unchanged across zoom. Method, fixed sigma, orientation, depth, filter version, and transform are cache-key inputs. **3-D is enabled** (`SUPPORTS_VOLUME_3D=True`): `_show_3d_volume_window` opens the shared `VolumeRenderWindow` passing (a) `render_method` (so the 3-D volume reflects the 2-D method — see 3-D volume preview) and (b) `_current_3d_region()`, the current 2-D view mapped to a native (X,Y,Z) box (in-plane axes from the view range per orientation, off-plane axis from the depth slider when active else the full extent) so the volume focuses on what's on screen. Region-focus is skipped (whole-data volume) for an overlay-transformed dataset. TIFF/image channels still use the inherited image path. **Fast interaction (production-parity):** `render_precision_gaussians` is **vectorized** — localizations are grouped by integer pixel footprint `(kh,kw)` and rasterized as batched `ndtr`+`bincount` ops (float64 accumulation) instead of a per-loc Python loop, giving the identical pixel-integrated, tile-independent result ≈10–16× faster (the single-loc halo test stays exact). On a view change the window paints an **instant coarse preview** (`_capture_preview_base`/`_resample_preview`: the previous same-orientation frame, nearest-neighbour resampled to fill not-yet-rendered tiles) then **fills precision tiles progressively** as workers finish (`_compose_precision_tiles(stage)` composites from whatever is cached over the preview — no longer all-or-nothing; `_on_precision_tile_result` coalesces a burst via `_progressive_timer`, `_PROGRESSIVE_COALESCE_MS=20`; auto-B/C settles only on the final `ready`/`cached` stage to avoid level flicker). Debounce is `_INTERACTION_DEBOUNCE_MS=45`. Tests: `tests/test_precision_render.py`.
- **Toned pure-colour LUTs.** `_map_norm_to_rgb` maps the pure-colour channels (`_CHANNEL_COLORS`: Red/Green/Blue/Cyan/Magenta/Yellow/Gray) via `pure_color_ramp(norm, color)` = **black → colour → white** (two linear segments), so the perceived **lightness** spans a full grayscale-like range and different pixel values stay distinguishable even for a saturated hue (plain `norm·hue` keeps e.g. full red only ~30 % as light as white). **Gray/white degenerate to plain black → white** (no mid-range white overshoot). Applies to single- and multi-channel composites (in overlaps bright features tend toward white — could be gated behind a toggle if that's unwanted). `pure_color_ramp` is a pure, unit-tested module function (`tests/test_pure_color_ramp.py`).
- **LUT dialog** (`ui/lut_dialog.py::LutDialog`; toolbar LUT button → `main_window._show_lut`). Fiji-style B&C + colormap editor over the owner window's histogram, **dataset-owned — one dialog per render / scatter / 3-D volume window, reused** (not a single shared instance). `make_colormap(name, *, invert=False, gamma=1.0)` builds the LUT (named colormaps + `_SINGLE_COLOURS` pure-colour ramps); **gamma** warps it (`apply_gamma`: colour at `t` = colormap at `t**gamma`). The min/max **level lines are draggable** (`_lo_line`/`_hi_line`, like the histogram filter bounds) and a dashed **gamma transfer curve is grabbable anywhere** — a left-drag on the histogram (custom `_GammaViewBox`) re-fits gamma so the curve passes through the cursor (level lines keep their own drag priority). **Opening the dialog must only *reflect* state, never change it** — `load_image` blocks the level-line signals around `setBounds`, else a stale `sigPositionChanged` fired the owner's level callback and re-scaled the plot to one colour. **Live auto-refresh:** owners call `sync_lut_dialog()` (→ `_refresh_lut_dialog(capture_baseline=False)`, which does **not** overwrite the Reset baseline) whenever colormap / brightness / **colour-by attribute** changes, and `_on_focus_changed` refreshes the focused window's open dialog, so it tracks the active view live. A **colour-by change auto-scales** (scatter `_on_color_by_changed` drops `_manual_color_levels` so the new attribute maps to its own range). `_show_lut` targets the focused/last plot view, scanning render / advanced-render / scatter registries **and each render's 3-D `_volume_window`** (`_open_lut_on_view` + `_lut_view_shows_dataset`). Regression: `tests/test_lut_dialog.py`, `tests/test_scatter_color_coords.py`, `tests/test_lut_button.py`.
- **Render right-click menu** (`_show_context_menu`, wired via `graphicsView.customContextMenuRequested`) **defers to a ROI right-click**: it maps the click to view coords and, if `_roi_overlay._record_at` hits a ROI, returns without popping the render View menu (so the ROI controller's own context menu isn't covered by the View menu).
- **White render background (`_white_bg`, per-window).** Right-click → **View › White background** toggles it (`_set_white_background`: flips `graphicsView.setBackground("w"/"k")` + `_compose_from_cache`). The render composite is **opaque** (alpha=1, black baked in), so a white background is **not** a view-background flip — it needs the colour model **inverted**. `_compose_rgba` therefore branches: black bg = **additive** (`rgb=Σ` colour ramps, bright-on-black); white bg = **subtractive** (`rgb=∏` per-channel `_channel_rgb_white`, starting from white — no signal stays white, signal darkens toward the hue, overlaps darken further, ink-on-paper style). `_channel_rgb_white` uses `pure_color_ramp(..., white_bg=True)` = **white → colour → black** for pure colours (gray → plain white → black, the classic inverted-LUT publication render) and `1 − colormap` for named colormaps. Localization mode only (TIFF/image mode unchanged); axis-label/ROI contrast on white is a follow-up. Regression: `tests/test_pure_color_ramp.py`, `tests/test_overlay_bc_independent.py`.
- **TIFF/image mode** supports 2-D grayscale, 2-D RGB, multipage stacks `(Z,Y,X)`, and RGB stacks `(Z,Y,X,C)`. Multipage stacks set `prop.num_dim=3` and reuse the depth slider: `All` = max projection; otherwise the selected slice/range labeled `slice N` / `slices lo-hi`. Pixel size is a placeholder `1.0 nm/pixel` (TIFF physical pixel metadata not parsed yet).
- **Axis labels:** when the axis is toggled on, `_set_axes_visible` calls `_update_axis_labels()`; `_axis_label_names()` returns orientation-based names (`X (nm)`/`Y (nm)` for XY, etc., `px` unit in image mode) and `_set_orientation` re-labels when axes are visible.
- **Brightness/Contrast is per-active-channel.** `_show_brightness_contrast` opens the always-on-top `BrightnessContrastDialog` and `_sync_bc_dialog()` points it at the **active** channel: `_active_channel_index()` (the `_channels` entry whose `dataset_idx == self._idx`, not the first-visible) drives `_bc_pixels()` and the `_on_levels_changed`/`_on_bc_auto`/`_on_bc_reset` targets, so editing levels writes only that channel's `ch["levels"]`. Switching the active channel re-targets it: `_on_channel_row_pressed` and the now-live `_on_active_changed` (updates `self._idx` when the new active is one of this window's channels) both call `_sync_bc_dialog()`. The histogram is drawn in **one representative colour** for the active channel (NOT a per-bin LUT gradient — bright bins were invisible on the white background): `_histogram_bar_color()` returns the channel's pure colour for solid-colour channels (`_CHANNEL_COLORS`), or the **mid (~127th) LUT colour** for gradient colormaps (`_channel_lut_rgb` via `_map_norm_to_rgb`), then `_luminance_clamped()` darkens too-bright colours (Yellow/Gray channels, the warm end of `hot`) toward `max_lum=0.72` so they stay readable on white (e.g. `hot`→orange-red, white→mid-gray; Red/Green/Blue pass through). Passed via `BrightnessContrastDialog.set_bar_color` → `HistogramPreview._pen_color`; no colour set → red bars (TIFF viewer keeps that default). **Overlay lookup:** the **main-window** `_show_brightness_contrast` (Shift+C target) must resolve the render window via `_render_window_for_dataset(active_idx)` — an overlay render window is stored in `_render_windows` under only its **anchor** dataset index but displays every channel, so keying strictly by the active index missed it when a non-primary channel was active and `_show_render` then spawned a **duplicate overlay view**. `_render_window_for_dataset` falls back to scanning each window's `_channels[*]["dataset_idx"]`. **`_show_render(idx)` itself now consults `_render_window_for_dataset(idx)` first** (`win = _render_windows.get(idx) or _render_window_for_dataset(idx)`) so **every** caller is covered centrally — e.g. segmentation's `add_segmentation_rois`/`add_point_rois_3d` calling `_show_render(idx)` on a non-anchor overlay channel reuses the overlay window instead of spawning a duplicate. Regression: `tests/test_overlay_brightness_contrast.py` (`test_shift_c_on_overlay_channel_reuses_window`, `test_show_render_on_overlay_channel_reuses_window`). **Per-channel `levels` are genuinely independent** — `_compose_rgba` `_normalized_tile`s each channel by its **own** `ch["levels"]` (non-active channels keep their own per-channel auto), and `_on_levels_changed` writes only `_active_channel_index()`'s entry; **no global `_manual_levels` is applied to a multi-channel composite** (`_manual_levels` is used only when `len(_channels)==1` or in image mode). The channels are then **additively** summed (`rgb += color·norm`, clipped) — so in **overlapping** regions changing one channel's B/C visibly changes the composite brightness there (expected, ImageJ-composite-style), even though each channel's own contribution is unchanged. Regression: `tests/test_overlay_bc_independent.py`.

## TIFF export
Render right-click **"Export to TIFF…"** (`render_window._export_to_tiff`, localization mode only) → `ui/tiff_export_dialog.py` (`TiffExportDialog` + `TiffExportWorker` QThread) → `core/tiff_export.py::export_render_to_tiff`. Reproduces the MATLAB `interactive_render_MINFLUX.m` Z-slicing export: each visible localization channel (filter + render transform applied via `_dataset_locs`, **native XYZ regardless of view orientation**) is binned into voxels (XY = pixel size, Z = voxel depth) and each Z slice written as the 2-D histogram of the localizations gated to that slice. Bit depth is chosen from the **global** max voxel count (`choose_dtype`: 8/16/32-bit), computed memory-cheaply via `np.unique` on linear voxel indices (no full volume materialized). Pages stream one at a time through a `tifffile.TiffWriter` (BigTIFF above ~3.9 GB); image convention is **rows=Y, cols=X**. Output is an **OME-TIFF** with `PhysicalSizeX/Y/Z` in nm (+ centimeter resolution tags), so `core/tiff_source.py` round-trips the calibration; multi-channel → one `CYX`/`CZYX` OME file with channel names.
- **Dialog options:** output path, XY pixel size, Z voxel depth, **X/Y/Z range** (editable nm spin pairs), and — for 3-D data — the **editable RIMF** (z-scaling). The XY range is pre-filled from the **active rectangle ROI** (`_active_rectangle_xy_bounds`: active draft or selected XY-plane rectangle, via `roi_selection.rectangle_bounds`) when present, otherwise the data extent (a note states which). `export_render_to_tiff(x_range/y_range/z_range=)` clips localizations to the box and spans the grid to it; `None` → that axis uses the data extent.
- **RIMF edit:** the spin defaults to the active dataset's `cali.RIMF`; changing it rescales the dialog's Z-range fields (`z*new/old`) and, on Export, is applied to the **active dataset** via `ds.set_rimf(source="manual (tiff export)")` + `state.notify_calibration_changed` (single source of truth — render/scatter update too); channels are then re-snapshotted so exported z matches the rescaled Z range. Multi-channel: only the active channel's RIMF changes.
- Progress + completion go to the **Log only** (no progress bar / completion pop-up); the worker is held in `_export_workers` and awaited in `closeEvent`. Gaussian smoothing is intentionally not applied (raw counts).

## Standalone image viewer (TIFF / OBF `.msr` series)
**Dropping a `.tif`/`.tiff`** (routed via `_route_file` → `_load_tiff`; there is **no** File-menu entry) opens a **dedicated, series-aware image viewer** (`ui/tiff_viewer_window.py::TiffViewerWindow`) — **not** a MINFLUX dataset (images stay outside the dataset model). Fiji-like: lazy plane reads, T/C spinners + a **horizontal Z-slice slider** (render-view style, with an `n/N` read-out), colormaps + pure-colour LUTs, ImageJ-style Brightness/Contrast (`Shift+C`), and an Info window (`I`) with OME-XML. **One window per file** (key `<resolved-path>#img` for TIFF, `#obf<raw>` for OBF), held in `main_window._tiff_windows`, opened via `_open_image_viewer(source, key)`.
- **View conventions.** Y is **inverted** (`ViewBox.invertY(True)`) — low Y on top, high Y at the bottom (Fiji / render-view convention). Axes + ticks are **hidden by default**; the right-click **Axis** entry (checkable) toggles them (`_set_axes_visible`, adds `X/Y (nm)` labels when shown).
- **Source abstraction.** The window is backed by any source exposing `metadata` (a `core/tiff_source.py::TiffMetadata`), `axis_size`, `read_plane(t,c,z)`, `close`, plus series helpers `series_names`/`series_summaries`/`set_series` and `metadata.series_count`/`series_index`. Two implementations: `TiffImageSource` (tifffile) and **`core/obf_image_source.py::ObfImageSource`** (`msr_reader.OBFFile`), which reuses `TiffMetadata` so the viewer needs no per-source branching.
- **Series switching (no chooser dialog).** A multi-series file opens **one** window; the in-window **Series combo** (bottom-left; `_on_series_changed` → `source.set_series`, drops manual levels + refits) flips series in place — hidden when `series_count == 1`. (There is deliberately no separate multi-select chooser; the dropdown supersedes it.)
- **OBF image series** are the OBF stacks `obf_image_source.is_image_stack` accepts (2-D `YX`, 3-D `ZYX`; a trailing 3/4 dim = RGB `S`), read via `read_stack` (cached whole-stack; `read_plane` slices Z). Pixel sizes come from `OBFFile.pixel_sizes` (metres → nm, aligned axis-for-axis with the numpy array; non-spatial >1 cm/px ignored). `series_index` addresses the filtered image list; `raw_stack_index` addresses the underlying OBF stack. `msr_is_image_only`/`list_obf_image_series`/`ObfImageSource._stacks` are header+footer-only scans and **must all use the same `is_image_stack` predicate**, or the viewer's Series combo and the export disagree about which series index means what.
- **⚠ `ndim >= 2` is NOT sufficient to identify an image — the MINFLUX payload can be 2-D.** Imspector stores the MFXDTA localization container as a plain `uint8` OBF stack, and real files (the whole `2026` Cigdem set) declare it **2-D**, a near-square block of bytes (`2575 x 2575`, `7301 x 7301`, …) with an **empty stack name**. The old shape-only rule therefore listed every MINFLUX blob as an image series and exported it as a multi-MB TIFF of container bytes. The discriminator is the stack **footer's `minflux` tag** (`OBFFile.stack_footers[i].tag_dictionary["minflux"]`, parsed by `_minflux_tag`): localization payload is JSON `{"type":"data", "did":…, "label":…}`; `{"type":"density"|"trace", "source":<did>, …}` are genuine derived images; plain confocal channels carry a small XML placeholder (not a dict) or no tag. `is_minflux_data_stack` reads that, falling back to the classic 1-D-`uint8` signature when a file has no tag. `classify_image_only` is built on the same two predicates.
- **MFXDTA stacks are deliberately not shown in the reader tree and not exported on their own.** They were briefly given a `MINFLUX data stacks` group + a Fields-dialog section + a `.mfxdta` blob export; **all of that was removed on review** — the tree already shows their contents as datasets, so listing the packaging too is noise. If a future task does need to show one, the agreed name is **"mfxdta container"**. What survives is the exclusion (`is_minflux_data_stack`) and the `.zarr` source-store export below.
- **`.zarr` export carries the embedded source store** (`msr_reader_dialog.export_source_store`, called per dataset from `export_parsed_result`): `unpack_zarr_store_to_dir(entry["zroot"], <stem>_mfxdta.zarr)`, **only** when `"zarr"` is among the formats. That container holds what the canonical flat table cannot — the acquisition `rois` (root `.zattrs`), the search grid (`grd/search_0`), the `used` bead list, and `acquisition_date` / `measurement` (sequence) / `scan_range` (`mfx/.zattrs`) — and unpacking costs one decode layer to yield a plain zarr v2 store any tool opens. Other formats skip it: a byte container has no meaningful `.mat`/`.csv` representation. `<stem>_mfx.zarr` remains the canonical, re-openable export; dragging `<stem>_mfxdta.zarr` onto the viewer is rejected with "missing required column(s): itr", which is correct. (History: `unpack_zarr_store_to_dir` sat unused with only tests for a while; an older CLAUDE.md line claimed it was wired to the `fmt_zarr` checkbox, which it was not.)
- **`source_did` links a derived image to its dataset.** `list_obf_image_series` returns it (`""` for a standalone confocal channel) from the tag's `source`. Note a `did` can be shared by two MFXDTA stacks (a run and its `_agg3000` companion), so the link is one-to-many in principle; the tree attaches such an image to the **first** dataset node carrying the did.
- **`.msr` always opens in the MSR reader** (`_open_msr_dialog`), even image-only files. Their OBF image series are reached from the reader three ways, all via `ObfImageSource(raw_stack_index=)` → the viewer (preferring the owner's `_open_image_viewer` registry, else held as a dialog child): (1) right-click an image node › **Open as image** or **Preview** (`_ctx_open_as_image`/`_ctx_preview` → `_open_obf_series`); nodes are tagged `nodeinfo` `image_series` (modern tree) or `legacy_series` (image-only tree) — both listed in `_IMAGE_NODE_TYPES`, which every consumer matches against; (2) select series in **Datasets / Fields included…** then **Open in MINFLUX viewer** (`_on_open_in_viewer` opens the checked images and, for image-only files, returns after). `_gather_image_series_for_dialog` = `list_obf_image_series(msr)` (works for legacy **and** modern files carrying confocal images). Tests: `tests/test_image_source.py` (pure helpers + TIFF series switch; OBF viewer test gated on the sample file).
- **Image series in the parsed-contents tree** (`_add_image_series_nodes`, modern mode): an image with a `source_did` nests under that dataset as an `Image series (N)` group parallel to `mfx`/`grd`; the rest go into one such group **beside** the datasets, as the root's last child. Both start **collapsed**, so `_add_image_series_nodes` runs **after** `_build_tree_from_result`'s expansion pass (that loop expands every direct child of the root and would otherwise open them).
- **Image selection is tri-state** (`MsrReaderDialog.image_field_selection`): `None` = **all** images of whatever each file has, a set of raw stack indices = exactly those, empty set = none. `None` is what the *Include all images* master checkbox in `FieldDialog` returns (`image_payload()`), and it is the only selection that survives a **batch over files with different channels** — indices address one file's stack table and names one file's labels. It must round-trip through `_save_settings`/restore as `null`, **not** as `[]` (that would silently mean "no images"). `select_image_series(series, names=, indices=)` is the one resolver: *names* wins, else `indices is None` → all, else that index set.
- **Exported image filenames keep the `.msr` name verbatim** (`image_export_stem`): `Ch1 {1}` → `Ch1 {1}.tif`. Only characters no filesystem accepts (`<>:"/\|?*`, control chars) are replaced — a run of them collapsing to one `_` — plus trailing dots/spaces and Windows reserved stems. Do **not** route these through `safe_export_stem` (the dataset sanitizer), which rewrites spaces and braces too and produced the unmatchable `Ch1__1_img.tif`. `export_image_series` takes the caller's `used` stem set so the per-series loop (which is what gives batch a per-image progress tick) still de-duplicates repeated labels.
- **MINFLUX acquisition ROIs live in the dataset's zarr root `.zattrs`**, not on any image stack: `{"rois": [{"corners": [[x0,y0],[x1,y1]], "type": "ROI", "linked_dta": <did>, "linked_cfg": "acquiring mfx", …}], "version": "2.1"}`, corners in **metres** in the same sample/stage frame as `mfx.loc` (verified: their union matches the dataset's localization extent to ~50 nm). These are the rectangles Imspector draws on an overview channel — nothing in the file binds a ROI to an image stack, so Imspector renders them on whichever image covers that stage region. Reachable in the reader tree (right-click the **dataset** node › **Show metadata**, `read_zarr_attrs(zroot, "")`) and read programmatically by **`msr/acquisition_roi.py`** — `read_acquisition_rois(path)` / `rois_within(rois, extent_m)` / `union_bounds(rois)`. That module scans the **raw file bytes** (mmap + a bracket-matched JSON slice, like `mfxdta.extract_did_label_map`) rather than decoding the MFXDTA container: the ROI is a few hundred bytes and decoding would read every localization blob (tens of MB). Not imported into the *dataset* ROI Manager — they are used for the image active ROI (below).
- **Image scan geometry** (`obf_image_source._scan_extent`): a confocal stack's footer `imspector` XML carries `ExpControl/scan/range/{x,y}` with `off` = the **centre**, plus `len`/`psz`/`res`; `res × psz == len`, and the frame is the same sample/stage frame as `mfx.loc`. Array **row 0 is the low-`y` edge and column 0 the low-`x` edge — no flip on either axis**: verified by projecting a run's localizations onto its own confocal image, where the direct mapping lands them on 3.3× background signal and a flipped `y` lands them on background (two independent image/dataset pairs). Derived stacks (density/trace) carry no scan range → `extent_m` is `None`. Cached per stack in `_scan_stacks`.

## Active ROI inside an image file (ImageJ-compatible)
ImageJ stores an image's **single active ROI** in the TIFF itself — the `IJMetadata` tag (50839, with byte counts in 50838) holding an ImageJ binary `.roi` record — and restores it on open. `core/tiff_roi.py` is our side of that contract, and it is **separate from the dataset ROI system** (`core/roi.py` + `ui/roi_overlay.py` + `ui/roi_manager.py`): one ROI, no store, no manager, because that is what the image format holds. Don't merge the two.
- **`core/tiff_roi.py`** (Qt-free): `TiffRoi` (the raw `blob` **plus** a decoded summary — the blob is authoritative and round-trips a shape we cannot model, e.g. a composite ROI); `decode_roi(bytes)`, `rectangle_roi(x,y,w,h)` (ImageJ bounds are integers, so it rounds **outward** — never drops a touched pixel), `roi_from_shape(type, bounds=|points=)`, `rectangle_roi_from_nm(...)` (returns `None` without a pixel calibration rather than guessing 1 nm/px), `roi_extratags(roi, byteorder, overlays=)`, `read_roi_from_tiff` / `read_overlays_from_tiff`.
- **One ROI per image, deliberately.** ImageJ's `Overlays` block could hold more (a second tier beside the active ROI) and the tiles of a tiled run were briefly written there; it was **removed on review** — individually the tiles only say where the beam dwelt inside an area the single box already delimits. Don't reintroduce it without a new reason.
- **Byte order is load-bearing.** ImageJ's metadata header/counts are read with the *file's* byte order, so `write_ome_tiff` pins `TiffWriter(byteorder="<")` and builds the tags with the same `TIFF_BYTEORDER`. A mismatch makes the whole block unparseable (tifffile warns `invalid ImageJ metadata header size`; ImageJ just shows no ROI).
- **Read it via the tag, not `TiffFile.imagej_metadata`** — that property is gated on the file being an *ImageJ* TIFF and our writer emits **OME**-TIFFs, which carry the tag perfectly well but report `is_imagej=False`. `TiffImageSource.active_roi()` + an `("Active ROI", …)` row in `raw_summary`; the ROI is a per-**file** block so it is only read for `series_index == 0`.
- **`export_image_series_to_tiff(source, path, roi=INHERIT_SOURCE_ROI)`.** The sentinel default means "carry the source's own `active_roi()`"; **`roi=None` means write no ROI**. They must stay distinct — with `None` as the default, deleting a ROI in the viewer and saving silently rewrote the source's ROI back into the file.
- **`ObfImageSource.active_roi()`** synthesises the MINFLUX acquisition area for the current series. `_single_run_rois()` = `read_acquisition_rois(file)` → `rois_within(extent_m)` → `group_by_dataset`, and returns `(label, rois)` **only when exactly one run** is inside; the label comes from `mfxdta.extract_did_label_map`. `active_roi()` is that run's `union_bounds` box (a run is tiled over 3–4 overlapping rectangles and an image holds one active ROI; the tiles themselves are not exported). **An image covering several runs deliberately gets no ROI** — merging across runs produced one box spanning the empty field between them, which marks nothing (that was the wide `Ch*{1}` overview). The file is scanned once and cached in `_acq_rois`/`_did_labels`.
- **⚠ Imspector draws a *different* rectangle on an overview: the child scan region.** It is the `ExpControl/scan/range` of the next, zoomed image — not a ROI record at all — and it is 3–10× larger than the acquisition ROI and unrelated to where the localizations are. The nesting is consistent across the sample set (75 µm overview → ~20 µm zoom → ~6–9 µm stack), and `Ch{1}`'s box is `Ch{59}`'s area while `Ch{59}`'s is `Ch{110}`'s. This was reported as an ROI-export bug; it is not one. If a future task asks to reproduce Imspector's on-screen rectangle, that is the object to export, via `_scan_extent` of the largest scan region strictly contained in the image.
- **`ui/image_roi_overlay.py::ImageRoiOverlay`** is the on-screen half, for `TiffViewerWindow`. The viewer draws images in **nm** (`ImageItem` at the origin, scaled by pixel size) while ImageJ ROIs are **pixels** — the overlay owns that conversion (`set_roi` scales in, `current_roi` scales out) so nothing above it handles two unit systems. It reuses `roi_overlay.py`'s `FilledRectROI`/`FilledEllipseROI`/`FilledPolyLineROI` so both overlays look alike. Drawing wraps `ViewBox.mouseDragEvent` (a drag would otherwise pan); `detach()` **pops the instance attribute** rather than re-assigning the saved bound method, so the class handler is genuinely restored. Rectangle/oval can be drawn; any loaded type displays and moves.
- Caveat worth remembering: ImageJ's own TIFF reader restores this ROI, but Fiji may route an OME-TIFF to **Bio-Formats**, which reads ROIs from OME-XML — tifffile cannot write those, so the ROI would not appear on that path.
- Regression: `tests/test_tiff_roi.py`.

## 3-D volume preview
Opened from render view right-click `View > 3D`. Owned by `RenderWindow` (closed in its `closeEvent`). File: `ui/volume_window.py`.
- **Scene coordinates are local, centered at (0, 0, 0).** Absolute nm coordinates cause black windows / camera precision failures.
- **Defaults:** XY + Z voxel both **2.5 nm** (isotropic; the auto-suggest in `refresh_from_dataset` is pinned to 2.5, not span-scaled). The **`Max dim` spinbox is auto-populated but user-adjustable**: on first refresh its range is widened to `_gl_max_3d_texture()` (the GPU's `GL_MAX_3D_TEXTURE_SIZE`, queried once via `makeCurrent`, **2048 fallback** = the GL 4.3 minimum) and its value set to `_recommended_max_dim()` = `min(gl_max, 2048)`; `_max_dim_initialised` guards the one-time seed. The two real limits are (a) `_DEFAULT_MAX_VOXELS = 8_000_000` (**total** voxels → RAM/compute; **usually the binding one for a whole-field cube**, giving ~200/axis regardless of Max dim) and (b) the GPU 3-D-texture size (**per-axis** → a longer axis fails to upload → black window; Max dim must never exceed it, hence the range cap). So raising Max dim only helps an **elongated or region-focused** volume where an axis wants >the cap but the total is still under 8M; for a big whole-field volume, resolution is bound by the 8M total (zoom into a region — region-focus honours 2.5 nm). Do not remove either cap.
- **Brightness/contrast** (`make_volume_payload(black_pct=, white_pct=)`, default `(0, 99.7)` = the historical auto-normalisation): black/white are **percentiles of the non-zero voxel counts** mapped to transparent/opaque; the window exposes **Black % / White %** spinboxes (`_on_contrast_changed` / `set_contrast_pct`). Opened from the advanced 2-D view, `_current_2d_contrast_pct()` expresses that view's active-channel B/C **levels as percentile ranks of its own scalar** and passes them (`contrast_pct=`) so the 3-D voxel visibility matches the 2-D image despite the pixel-vs-voxel scale difference. `norm = clip((volume−vlo)/(vhi−vlo))`, `vlo/vhi` = those percentiles; `intensity_max` = `vhi`. Same params on `make_multichannel_volume_payload`.
- **Per-method single-channel volume** (`make_volume_payload(render_method=, precision_sigma_nm=)` → `_voxelize_volume`): the advanced view passes its 2-D `render_method` so the volume reflects it — `histogram` = crisp (no blur); `bilinear`/`bicubic`/`basic` = a `_METHOD_VOXEL_BLUR` sub-voxel smoothing (0.6/0.9/0.5 voxel — a voxel grid can't show a splat kernel's sub-voxel shape, so a small blur captures the "smoother than histogram" character); `fixed_gaussian` = `sigma_nm_xyz` blur; `precision_gaussian` = **true per-localization** anisotropic 3-D Gaussian via `_precision_volume_3d` (sigma-binned: group locs by mean precision, histogram + `gaussian_filter` per bin at the bin's median sigma, sum — O(bins·voxels), the "big" precision 3-D). **The per-bin blur is `hypot(precision_nm/voxel, _MIN_VOXEL_BLUR=0.75)`** — a minimum anti-alias floor: when the **8M total-voxel cap** (`_DEFAULT_MAX_VOXELS`, the real resolution limiter — *not* Max dim or the requested voxel size) forces a coarse voxel on a large FOV, the nm precision becomes sub-voxel (e.g. 2.5 nm / 12 nm ≈ 0.2 voxel) and a raw histogram would render **pixelated/blocky**; the floor keeps it smooth like the base render (blocky isolated voxels 83%→0% in tests). True fine (2.5 nm) 3-D detail needs **region-focus** (a 3 µm FOV can't be voxelized at 2.5 nm — 1.7 B voxels); zoom into a structure in 2-D before opening 3-D. `render_method=None` reproduces the original histogram+0.75-voxel-fallback behavior (the basic render window's 3-D is unchanged). Per-loc native-XYZ sigma is resolved by `VolumeRenderWindow._single_channel_locs` (aligned to the filter+finite mask). **Region-focus:** `_clip_region` restricts locs (+ aligned sigma) to the advanced view's `region_bounds` box. Multi-channel overlay volume is unchanged (no per-method/precision yet).
- `_DEFAULT_MAX_VOXELS = 8_000_000` is the real cap. Do not remove it.
- `MIP` mode is a single Z-axis projection — do not change it back to three orthogonal planes.
- Do not add VisPy (that experiment was discarded). OpenGL axis/bounding-box overlays must stay toggleable; always-on helpers caused repeated GL draw warnings.
- **Multi-channel overlay volume.** When the anchor dataset is part of an overlay, `_overlay_channels()` (via `overlay_members`) gathers every channel's transformed filtered locs + LUT colour, and `make_multichannel_volume_payload` composites them into ONE RGBA volume on a **shared grid**: each channel is voxelised, normalised to its own 99.7-pct, and **additively coloured** (`lut_rgb` → pure-colour RGB / colormap-bright sample; red+green overlap → yellow), per-voxel alpha = max channel response. `_volume_grid` is the shared grid helper (factored so single- and multi-channel use the same extent/voxel logic). The `Colormap` combo is ignored in overlay mode (each channel uses its LUT); `Surface` iso mode still colours by the summed norm. Single datasets use `make_volume_payload` as before. The **scatter** 3-D view already composited overlays (`_draw_overlay_3d`). Tests: `tests/test_volume_multichannel.py` (pure compositing + `lut_rgb`).
- **LUT dialog on the 3-D volume.** `VolumeRenderWindow.open_lut_dialog` opens the shared `ui/lut_dialog.py::LutDialog` for the volume view (reached by the toolbar LUT button when the volume window is the focused/active view — `_show_lut` scans each render's `_volume_window`). Dragging the dialog's level lines maps (lo, hi) back to the volume's native **Black %/White % percentiles** (`_on_lut_levels_changed`); the colormap + **invert** flow through `_on_lut_cmap_changed`/`_on_lut_invert_changed` (persisted to `ds.state["render_channel_lut"]`, `self._lut_invert`). `make_volume_payload(..., invert=)` + `_matplotlib_rgba(..., invert=)` honour it, with a `make_colormap` fallback for LUTs not registered in matplotlib (glasbey, etc.). Regression: `tests/test_volume_window.py::test_make_volume_payload_supports_inverted_lut`.

### Plot Profile (ImageJ-style, `ui/plot_profile_dialog.py` + `analysis/plot_profile.py`)
**Analyze › Measure › Plot Profile** plots localization **density (loc/µm²)** along a **line / polyline / freehand-line** ROI vs distance-from-start (nm), **live-updating** as the ROI is drawn/edited. It **samples the localizations directly, not the render raster**, so the profile is decided purely by the data — **independent of the render viewport / zoom / LOD / LUT** (this fixed the old raster approach's bugs: the intensity changing with zoom, and the profile vanishing / the app hanging when the line + band left the current view). Works on a **render or a scatter** view: `_show_plot_profile` resolves the active 2-D coordinate view (`_active_coordinate_view`, else the dataset's render window) and requires it to expose `profile_localizations()`; if no open-line ROI is active it activates the **line** tool so the user can draw one and watch the profile appear.
- **Localization source (shared):** `core/roi_crop.py::plane_localizations(state, channels, plane)` = the visible non-image channels' `display_xyz_filtered` (loc_nm + overlay transform + filter mask) projected into the plane's two axes; `plane_localizations_version(...)` is a **cheap token** (dataset idx / filter-mask sum+len / RIMF / visibility / plane) that changes only when the data would — **not** on zoom/pan. Both render and scatter expose `profile_localizations()` / `profile_locs_version()` over `self._channels` (fallback single-channel). Depth-range/slider is deliberately **not** applied (a data-decided profile, not a view slice).
- **Pure core `analysis/plot_profile.py`** (Qt-free, unit-tested): `line_profile_from_locs(locs_xy, path, width_nm, *, bin_nm=None, n_bins=256)` assigns each localization to the **nearest segment** of the (poly)line, keeps those within `±width/2` perpendicular, and histograms their **arc-length** position → `(centres_nm, counts, bin_width)`. A **global + per-segment bbox cull** keeps it O(N): a 270 k-loc straight line ≈ 1.5 ms, a 48-segment field-spanning freehand ≈ 7 ms. `band_polygon`/`resample_path`/`path_cumlen` are the shared polyline geometry. (The old raster `sample_line_profile`/`_bilinear` were removed.)
- **Dialog** (`PlotProfileDialog`, non-owned modeless via `show_modeless`, binds to `self._view` = render **or** scatter): a pyqtgraph curve + **Line width (nm)** + **bin (nm)** (`0`=auto) spinboxes + Save CSV + a **hover read-out** (snap-to-nearest dashed crosshair + dot + `d = … nm / ρ = …` label via `scene().sigMouseMoved` → `_on_hover` → `_nearest_profile_point`; `_label_anchor(dx, dy, x_range, y_range)` flips the label **left** near the right edge and **below** the point in the upper half so a peak's label isn't clipped). Counts → density = `counts / (bin_len·width) · 1e6` (loc/µm²). It **polls** the bound view (`_POLL_MS=80`, ~12 fps) for the active open-line ROI (`RoiOverlayController.active_open_line_record()`) — polling because a *draft* line drag emits no store signal — reading its **live pyqtgraph item** vertices via `active_open_line_points()` (which reads `item_to_geometry` off `draft_item`/`items[id]`, falling back to the record geometry) so the curve + band track a **drag in progress** (Fiji-style live update), not just the record geometry that commits on `sigRegionChangeFinished` (release). It **re-fetches the localizations only when `profile_locs_version()` changes** (so zoom/pan/idle ticks do nothing; the signature `(width, bin, live-path, version, colour)` changes each poll during a drag → curve/band recompute, but the loc fetch stays gated on the data version). The **width band** `QGraphicsPathItem` (fill alpha ≈ 45 + a **cosmetic** edge pen alpha ≈ 170, the ROI's `stroke_color`) is added to `coordinate_view_box()` at **z=5** (above the opaque render `ImageItem` at z=0, below the ROI handles at z=11 — a negative z hides it behind the render), tracks the line + width live, and is **removed on close**. `_alive()` guards against the view being closed underneath it. Tests: `tests/test_plot_profile.py` (pure), `tests/test_plot_profile_ui.py`.

### Trace read-outs (`As`) — one registry
`utils/filters.py::TRACE_AGG_FUNCS` is the **single** label→function map for every trace aggregation: `trace mean · median · min · max · 1st · last · stdev · range`, in dropdown order. `AGG_MODES = ["per loc"] + list(TRACE_AGG_FUNCS)`, and both the histogram's `As` and the Filter dialog's `Mode` are built from it, so they can never diverge. Everything dispatches through `trace_agg_func(mode)` — `filters.aggregate`, `filters.compute_filter_mask`, `filters.raw_spec_mask`, `filters.raw_trace_aggregate`, `histogram_window._aggregate`, `filter_dialog._filter_spinner_values`. **Adding a read-out = one entry here.** An unknown mode **raises** (it used to `return vals`, silently yielding one value per *row* where the caller promised one per *trace* — that bug hit `trace 1st`/`trace last` on the raw path and `trace median` in both mask builders).
- **`1st`/`last` are positional, not order statistics** — the trace's first/last row in store order (localization-major, iteration-minor), so under a single-iteration selection they are its first/last localization and under `all [flatten]` its first/last raw row. Taken literally (no NaN skipping); `min`/`max` remain NaN-skipping order statistics. `FLOAT_RESULT_MODES` (`mean/median/stdev/range`) are derived statistics → float bounds; `min/max/1st/last` return a data value → keep an integral source integral.
- **Trace read-outs × iteration selection compose as expected**, verified numerically over the whole matrix: the trace statistic is computed from the per-localization values **at the selected iteration**. `trace mean` + `last` = mean of the last-iteration values; `trace mean` + `all [average]` = mean of each localization's iteration-average (a genuine two-stage computation). `all [stacked]` runs `_raw_values` per iteration `k`, so each series is a real trace-level statistic at that iteration — well-defined, and correctly absent from the filter.
- **`all [flatten]` pools every raw row with equal weight** — nothing is scaled by iteration index. A trace read-out under flatten therefore runs over that trace's `n_loc × n_itr` rows, so localizations with more iterations carry more weight. Accepted trade-off, asserted in `tests/test_trace_aggregation.py`.
- **A trace read-out deliberately IGNORES the active filter** (`_aggregate`'s `ftr` argument is unused for trace modes; `per loc` does honour it). A trace's mean/median/… is a property of the trace, so it must not shift while an unrelated filter is tuned. To get filter-aware trace values, save a filtered copy (`content="snapshot"`, `filter_mode="apply"` → rows dropped) and reload it — verified round-trip for `.csv` and `.mat`. Note `build_snapshot_table` bakes the **persisted `filter_specs`**, not a hand-set `ds.filter_mask`, so a mask set only via the scripting API is not applied.

## Filter / histogram rules
- `Filter...` only opens the active dataset's dialog (does not open a histogram).
- Outside filter edit mode, histogram updates from filter toggles preserve x-range, y-range, and bin size — bars shrink in place. Do not auto-rescale.
- Filter edit-mode actions: `Update Filter` (apply, stay), `Finish Edit` (apply, exit), `Cancel Edit` (restore snapshot, exit). Double-left-click triggers edit; double-right-click must not. Attribute change in edit mode resets bounds to current histogram range. `Log(data)` maps bounds through log/exp. `per loc` / `trace mean` / `trace median` preserve bounds; trace `min/max/stdev/range` reset to data range.
- `histogram_window._filter_style()` converts `prefs["plot"]["filter_range_alpha"]` from a **0–100 percentage** to 0–255 at draw time.
- `HistogramWindow.start_filter_edit()` must redraw **before** assigning `self._filter_edit`; otherwise redraw paths detect an active edit and clear it immediately (green bounds / report label / edit buttons disappear).
- Filter Min/Max cells and the "Filter bounds" popup use `filter_dialog.py::SmartBoundsSpinBox`: bool shows/steps only `0/1`; int/uint shows no decimals and steps by a data-range-derived power of 10 (min 1); float shows 3 decimals and scientific notation for very small/large values (metre-scale `loc_x/y/z`). Step = `10 ** (floor(log10(max-min)) - 1)` (e.g. `62500..146000 → 1000`, `0.337..0.905 → 0.01`). Bound kind follows `FLOAT_RESULT_MODES` (see Trace read-outs).

### Histogram right-click: Zoom + Reset View
`_show_plot_context_menu` (defers to a ROI right-click, like the render view) offers a **Zoom** submenu — `horizontal · vertical · unconstrained` (`HistogramWindow.ZOOM_MODES`) — plus **Reset View** (identical to the top-right `Reset` button: clears the manual bin width, redraws, refits).
- Arming a mode wraps `ViewBox.mouseDragEvent`; the cursor becomes a crosshair (left-drag normally pans, so it needs an affordance). It is **one-shot** — `isFinish` calls `_set_zoom_mode(None)`, so the next drag pans again. `Esc` and `Reset View` also disarm.
- Guides ride at the **cursor** (horizontal 'H' at the mouse's y, vertical at its x), *not* at the view middle, so they can be lined up against the bars.
- **`horizontal` and `unconstrained` re-bin and then re-fit the height** (`_auto_y_for_x_range`, read off the drawn bars so it reflects the bin width in use): a finer bin splits each bar's counts, so the pre-zoom (or drawn) y range would leave the zoomed peak squashed. Consequence: unconstrained's drawn **height is superseded** by the fit; it effectively sets X only. `vertical` changes neither X nor the bin size.
- **All three clamp `y0` at 0** — counts are never negative. Panning is untouched and may still show the sub-zero band.
- `_zoom_bin_width` targets a bin **count** across the zoomed span (`_ZOOM_VALUES_PER_BIN=4`, clamped `_ZOOM_MIN_BINS=10`…`_ZOOM_MAX_BINS=60`). **Do not reintroduce Freedman-Diaconis here**: it trades span for sample size (a 10× zoom refines only ~4.6×), and on a window holding a sharp concentration its IQR collapses and it demands thousands of sub-pixel bars — measured 1952 bars, 91 % of count ≤1, which the height auto-fit then stretched into one solid block. Width is floored at `full_span/_MAX_HISTOGRAM_BINS` because `_bin_edges_for` bins over the **full** data range and caps it at 4096, which also limits useful zoom to ≈68× (past that the window gets fewer than the targeted bars). Same cap silently clamps a hand-typed tiny bin size — open work.

## Keyboard shortcuts
Preference-backed shortcuts are updated in `_apply_shortcuts()`. Keep `_SHORTCUT_LABELS` (preferences_dialog.py) and `_shortcut_actions` (main_window.py) in sync. Regression: `tests/test_global_shortcuts.py`. (History: an earlier iteration made the menu actions `ApplicationShortcut` instead; that was replaced by this event-filter approach — do not reintroduce a parallel `ApplicationShortcut`/`_GlobalCloseFilter` path, it double-fires with the event filter.)

Writing a store to disk happens only in the **`.zarr` export** (`fmt_zarr` checkbox → `export_source_store` → `unpack_zarr_store_to_dir(zroot, out/<stem>_mfxdta.zarr)`, alongside the canonical `<stem>_mfx.zarr`); see the OBF section above. The "Temporary folder" pref is now only a fallback export dir, not a cache.

## Sample data (Data Simulator)
Synthetic **MINFLUX-like** datasets. Two entry points:
- **Plugins › Data Simulator** (`plugins/data_simulator/`; window `ui/data_simulator_window.py`) — the full UI: configure a structure + sampling, **Generate now**, and **manage the presets** that appear under *File › Open Sample Data* (add / update / rename / remove / reorder + save/load a JSON preset file). Registered **immediately under ParaView** (import order in `plugins/__init__.py::ensure_loaded`; Script Editor moved to the bottom).
- **File › Open Sample Data** (`menuOpenSample`, a submenu rebuilt by `main_window._rebuild_sample_menu` from the persisted presets; **excluded from the command finder** like Open Recent). Each entry **silently regenerates** its dataset(s) from the saved config via `generate_simulated(preset)`.
- **Engine `core/simulate.py`** (pure NumPy, Qt-free, seeded, unit-tested): a **structure template** (`STRUCTURES`: `homogeneous` / `clusters` / `npc` (8-fold two-ring) / `microtubule` (hollow filaments) / `sphere` / `cylinder` / `cube` / `pyramid`, each a generator + `ParamSpec` list with hover `desc`) places `n_points` molecules; `simulate_localizations(...)` expands each into a **Poisson(`locs_per_trace`, ≥1) trace** jittered by `precision_nm` (real `tid`; `dim=2` flattens Z). Per-loc attributes (`simulate_attributes`) are canonical MINFLUX columns from characteristic distributions (`efo` log-normal, `cfr`/`dcr` Gaussian clipped [0,1], `eco`/`ecc` Poisson counts, `fbg` Gaussian).
- **Non-overlap constraint.** Distinct **structure instances cannot spatially overlap** (real biology): `place_nonoverlapping(n, min_dist, rng, disk_radius|box_half)` (grid-hashed rejection sampling; **cell = `min_dist`** so the 3×3 neighbourhood catches every conflict — a smaller cell silently missed neighbours) places up to `n` instance centres ≥ `min_dist` apart (fewer if the field is too dense). Applied to **NPC pores** (`gen_npc` + `_npc_scaffold`, `min_dist ≈ diameter`; the scaffold uses the **largest** channel diameter), **cluster centres** (`~4σ`), and **microtubule filament seeds** (`~4·diameter`). **This is per-scaffold** — the co-registered channels of one overlay share ONE scaffold and *are* allowed to overlap (different labelling of the same pore), distinct from separate pores which don't.
- **NPC membrane curvature.** `gen_npc` places pores on a spherical cap: **`field_curvature`** (0 = flat → 1 = a hemisphere over the FOV, so edge pores tilt up to 90° — axial tilt = local surface angle) + **`local_tilt_deg`** (extra random per-NPC tilt) tilt each NPC's two-ring plane along the local surface normal — for testing particle-average algorithms against a spread of axial tilts (mimics NPCs on a curved nuclear envelope). Both carry tooltip descriptions.
- **Multi-channel / spectral sims (`MULTI_SIMS`).** Beyond the single-structure `STRUCTURES`, `core/simulate.py` has co-registered multi-channel recipes keyed with a `sim_kind`:
  - **`npc_overlay_3ch`** (`kind="overlay"`, `simulate_npc_overlay`): **3 labelling channels on ONE shared pore scaffold** (`_npc_scaffold` → pore centres + per-pore ring-plane frame; each channel = `_npc_channel_subunits` with its own diameter / inter-ring / axial offset). The channels are **co-registered** (same scaffold, curvature + tilt), so this is the test data for **multi-channel particle averaging**. `main_window._generate_sim_overlay` builds them as an overlay (Red/Green/Blue).
  - **`npc_dcr_2ch`** (`kind="dcr"`, `simulate_npc_dcr`): **two reporters (outer + inner ring) on one scaffold, mixed into a SINGLE dataset** whose `dcr` attribute is **bimodal** — the channels are recoverable only via *Process › Channel › Separate Channel by DCR*. `main_window._generate_sim_dcr` adds one dataset with the bimodal `dcr`.
  - Registry accessors `param_specs(key)` / `sim_kind(key)` / `default_params` / `structure_labels` span both `STRUCTURES` and `MULTI_SIMS`; the Data Simulator config widget builds their params and **disables the channels/3-D controls** (they define their own). `_expand_to_localizations` is the shared molecule→Poisson-trace step.

## Spreadsheet import (generic localization tables)
**Dropping a `.csv`/`.tsv`/`.txt`/`.xlsx`/`.xlsm`** (routed via `_route_file` → `_load_csv`/`_load_spreadsheet`; there is **no** File-menu entry) **always opens the column-mapping dialog** pre-filled with a best guess — never a silent import — so the user confirms/corrects the mapping before import. Core is `core/spreadsheet_loader.py` (pure, unit-tested); UI is `ui/spreadsheet_import_dialog.py::SpreadsheetMappingDialog` (entry `import_spreadsheet(path, prefs, parent)`).
- **Header detection + positional names.** `_is_header_row` treats a first row whose every non-empty cell parses as a number as **data, not a header** → the row is kept as data and columns are named **positionally** `"1st column"`, `"2nd column"`, … (`_ordinal`), which is what the dropdowns/preview show (not the first data value). A row with any text cell is a header (unchanged).
- **Value-based auto-detection.** `read_table` → `SpreadsheetTable`; `guess_mapping(table, use_values=True)` maps roles **header-first** (per-role synonym sets, tool detection for ThunderSTORM/SMAP/Picasso), then for any still-unfilled localization role fills from **column value statistics** (`column_stats`, cheap vectorised numpy: `is_integer`, `vmin`/`vmax`/`ptp`, `median_abs_diff`, `n_unique`, `mean_count_per_unique`, **`frac_increasing`** = fraction of steps ≥ 0). **Detection order (matters): tid → frame → x/y → z.** A **tid** is integer with `10 < n_unique < 10000` and mean repeat `2…1000`. A **frame/tim** is the first **monotonic** column (`frac_increasing ≥ MONOTONIC_FRAC=0.9`) — a timestamp/index increases while a coordinate scatters; detected **before** coordinates so a timestamp (whose span can look coordinate-like) is claimed here, **not** mistaken for x. A **coordinate** is a **scattered** (non-monotonic) column whose span fits a MINFLUX FOV (`COORD_MIN_SPAN_NM=5` … `COORD_MAX_SPAN_NM=1e4` nm) in some length unit — x/y are the first two, **z is the column right after y** evaluated in the **shared** coordinate unit (a flat axis `< 5 nm` stays 2-D → z unmapped). *(This is the fix for a metres file `tid, time(s), x, y, z` where the seconds column's span read as ~1000 nm and was grabbed as x — monotonicity now sends it to `frame` first.)*
- **Unit guessing from magnitude.** `guess_length_unit_from_span(ptp)` picks the coarsest of `nm/um/mm/m` whose span stays ≤ `SANE_MAX_SPREAD_NM` (so nm-scale numbers read nm, µm-scale read µm, metre-scale read m). `guess_units` uses the header unit if present, else Picasso→`px`, else **one shared value-based unit for all coord axes** (from the largest-span axis, so a small 3-D z inherits x/y's unit). `time_unit_guess` gives the frame column's **unit**: integer→`None` (frame index, kept as-is), float median step `< 0.1 s`→`"s"`, `0.1…50`→`"ms"`. `build_dataset_from_mapping(..., time_unit=)` rescales `frame`→canonical `tim` **seconds** (`"ms"`→÷1000).
- **Dialog** pre-fills role combos + coord unit combos + a **time-unit combo** (`s`/`ms`/`frames`) + pixel size (from `prefs["data"]["pixel_size_nm"]`) from the guesses; each numeric column's stats (dtype · range · median step · unique count) show as a hover tooltip on the role dropdowns. `x`/`y` required. The headless `auto_import` stays header-only (conservative) for programmatic/back-compat use. Tests: `tests/test_spreadsheet_loader.py`, `tests/test_spreadsheet_autodetect.py`.

## Flat-table re-import (round-trip of saved data)
`core/loader.py::_flat_table_from_dict` detects a **flat localization table** — a dict of 1-D columns with `xnm`/`ynm` (or `x`/`y`) and **no structured mfx `loc`** — i.e. the layout written by Save Processed Data. It's hooked into `load_dataset` (`.mat`, right after `_load_mat`) and `load_npy` (structured array → dict) so those don't get fed to the mfx parser (which needs a `loc` field and would lose the coordinates / misread a constant `itr`). `.json`/`.csv` already handle `xnm/ynm` via `load_json`/`load_csv`. Re-imported coordinates are **final/processed**: RIMF is pinned to 1.0 and `ds.derived["rimf"]` is set so the post-load auto-RIMF estimation is suppressed (otherwise a 3-D z would be double-corrected); derived attrs are recomputed; a saved `ftr` column restores the filter mask.

## Save / Export data
`File > Save Processed Data…` (`main_window._save_data` → `main_window.save_dataset(ds)` → `ui/save_dialog.py::SaveProcessedDataDialog` → `core/save.py::save_processed`). `_save_data` saves the **active** dataset; `save_dataset(ds)` is the reusable entry the **Dataset Manager right-click "Save as…"** (`dataset_manager._show_context_menu`/`_save_dataset`) calls on the **selected** row's dataset. **Unified save/export/convert** — full design in `docs/save-export-design.md`. Two orthogonal axes:
- **Data content:** **raw canonical** (the all-iteration `mfx` as an m2410 structured array via `dataset_to_mfx_array`; reloads through the normal parser + recipe) OR **processed snapshot** (`build_snapshot_table`: last-valid view with RIMF + per-dataset transform + filter **baked** into `xnm/ynm/znm`, optional frozen derived attrs).
- **Recipe sidecar** (`<stem>_metadata.json`, tagged `METADATA_JSON_MARKER="minflux_viewer_metadata"`, a dict): include or not, independent of content.
- **Canonical RIMF rule — "baked XOR recipe":** correction lives *either* in the numbers *or* in the recipe, never both. Raw → unscaled `loc_z` + `rimf` recorded in the recipe. Snapshot → coords baked + `build_metadata(content="snapshot")` pins `rimf=1.0` and clears `transform`/`filters` (originals kept under `*_baked`). RIMF is **not** folded into the transform matrix. The flat-table re-import already pins `RIMF=1.0`, so a baked snapshot is never re-corrected.
- **Formats:** `.mat`/`.npy`/`.json` write the structured mfx (raw) or a structured table (snapshot, via `columns_to_structured`); `.csv`/`.npz`/`.zarr` take flat columns (`flatten_mfx_array` splits `loc→loc_x/y/z`, `dcr→dcr_0/1` with the loader-recognized names — CSV normalizes legacy/m2205 to the m2410 flat layout). `.csv`/`.json` round-trip via `load_csv`/`load_json`; `.npz`/`.zarr` write-only for now (read path is BACKLOG). **`.msr` is now a first-class save format** (`DATA_FORMATS`/`_EXT` include `"msr"`; `save_processed` `fmt="msr"` → `msr/writer.py::write_datasets_msr(path, [ds])`, the custom OBF/MFXDTA round-trippable writer). It is **raw-only** (`_RAW_ONLY_FORMATS`): a processed snapshot would be re-corrected on reload (the MSR reader doesn't consume the recipe sidecar → auto-RIMF double-scales the baked z), so `content="snapshot"` + `msr` **raises** `ValueError`, and the dialog pins `.msr` to raw content (shows a "(custom .msr writer; may not open in Imspector)" note, disables the content combo). The old **File › Export to .msr** menu entry (`actionExportMsr`/`_export_to_msr`) was **removed** — save to `.msr` like any other format (per-dataset; overlay channels save individually, no group-linking, matching every other format). Preferences ▸ Data ▸ "When saving/exporting data file:" lists `.msr` on **its own row** below the other format checkboxes with the disclaimer (default enabled; `_EXPORT_FORMAT_DEFAULTS` + `export_formats` default include `"msr"`).
- **Filter handling:** snapshot `filter_mode` = `apply` (drop filtered rows) or `flag` (keep all + an `ftr` boolean column); plus the filter definition can also be saved in the recipe (`filter_specs`).
- **Preferences > Data → "When saving/exporting data file:"** holds defaults (`export_formats`, `export_content`, `export_include_*`, `export_filter_mode`) that shrink the dialog: it shows path + format (enabled-only) + content (a dropdown only when both are enabled) + a **"More options…"** expander. File-backed raw keeps the recipe-only shortcut (`data_path=None`).
- ROIs are saved **separately** (ROI Manager native JSON), not by the data save; overlay is recorded only as per-dataset info (no group linking). Existing raw + `.mat/.npy/.json` behaviour is unchanged, so `tests/test_save.py` still holds; new behaviour is in `tests/test_save_export.py`.

## Localization precision
`analysis/localization_precision.py` implements three estimators, launched from **Analyze › Localization Precision** (`actionLocPrecisionStdDev`/`Crlb`/`Frc`, `run_stddev_per_trace`/`run_crlb`/`run_frc`); each shows a modeless result dialog and logs a result line via `_try_journal` (→ `journal.add` **and** `state.log`, so it lands in the log history).
- **StdDev per trace** (`stddev_per_trace`): per-trace σ over traces with ≥ `MIN_LOCS_PER_TRACE` (5) localizations, raw z (no RIMF). Also the on-load auto-compute (`compute_loc_prec` pref) → `ds.cali.loc_precision` + `ds.derived["sigma_per_trace_nm"]`. Ref: Ostersehlt et al. 2022.
- **CRLB** (`crlb_precision`): the **MINFLUX targeted-donut** Cramér-Rao bound (Balzarotti 2017; Marin & Ries arXiv:2410.12427, 2024) — **not** the camera/Gaussian bound (Mortensen 2010). Per-loc σ from `eco` (N) + measured SBR (`efo`/`fbg`) + editable pattern `L`/donut `σ_q` (`L_z` for 3-D); dialog recomputes on L/σ_q change. Requires `eco`.
  - **Per-dimension photon count (3-D).** The materialized `eco` is the photons at the **final axial (z) iteration** — correct for σ_z but **too few for σ_xy**, whose photons come from the **final lateral (xy) iteration** (a different loop iteration, typically more photons). `run_crlb` detects the lateral/axial iterations via `core/mfx_sequence.py::photon_iterations_for_dataset(ds)` and gathers the lateral `eco` with `core/loader.py::iteration_attr_values_1d(ds, "eco", lateral_iter)` (aligned to the last-valid rows via `_gather_iteration_values`/`_raw_loc_id`), passing `crlb_precision(eco_xy, …, eco_z=eco_axial)`. `crlb_precision` gained optional `eco_z`/`efo_z`/`fbg_z` (default = the lateral values → **backward-compatible single-`eco` behaviour**, all old tests unchanged); result carries `median_n_z` + `per_dimension_photons`. On the reference file this lowers median σ_xy ≈2.47→2.03 nm (σ_z unchanged). Falls back to the single materialized `eco` when the raw store can't supply the lateral iteration (e.g. `iter_load` materialized without `mfx_raw`). Reference/ImSpector aside: neither pyMINFLUX (uses `eco_index = num_iter−1`) nor the DNA-PAINT code sum/pick per-dimension photons — this is our correction. Tests: `tests/test_localization_precision.py::test_crlb_per_dimension_photons`/`test_crlb_backward_compatible_single_eco`.
  - **Precision budget** (`run_crlb` + `CRLBResultDialog._add_precision_budget`): the CRLB dialog also cross-links the *measured* per-trace σ (`_measured_trace_precision` → `stddev_per_trace`, raw z) to the bound via the Marin & Ries 2026 (SimuFLUX) decomposition **STD² = σ_fl² + σ_CRB²** → excess **σ_fl = √(STD² − σ_CRB²)** (`excess_precision`, pure/tested), the photon-count-independent error (flickering/drift/vibration/misalignment) beyond the photon limit. Shown only when per-trace measured precision is available; recomputes with L/σ_q; the SimuFLUX citation + a decomposition note are added to the dialog only when the budget is present.
- **FRC** (`frc_resolution`): Fourier ring correlation, 1/7 threshold. Ref: Banterle et al. 2013 + Nieuwenhuizen et al. 2013.

## Aggregation (Imspector-style) & photon-bearing iterations
**Process › Aggregate Localizations…** (`main_window.actionAggregate` → `_aggregate_active_dataset`, dialog `_ask_aggregation_threshold`) reproduces Abberior **Imspector's "Aggregation"** post-processing from raw MINFLUX data. Core `analysis/aggregation.py` (pure NumPy, unit-tested); reverse-engineered from reference raw/aggregated file pairs and validated **end-to-end on a real `.msr` to ≈99 %** (98.99 % exact photon match, 0.27 nm median position, 100 % begin/end flags, 99.96 % exact point count).
- **What it is:** per-trace **photon-threshold binning** — the `aggN` in an Imspector filename (`agg3000`) is a **photon threshold, not a point count**. `aggregate_localizations(raw, photon_threshold, photon_iters)`: keep **valid final** localizations (`fnl==1 & vld==1`); group by `tid`; walk each trace in **time order** accumulating the localization photon count until it reaches the threshold, then emit one **mean-position** point (summed photons, mean time), reset, and emit the trailing remainder; flag `bot`/`eot` on the first/last point of each trace. `aggregate_dataset(ds, …)` builds the `raw` dict from `ds.mfx_raw` (which preserves `fnl`/`vld`/`itr`/`eco`/`tid`/`tim`/`loc_*` for flat m2410 `.msr` data; `dcr` is rebuilt as `(n,2)` from the split `dcr_0`/`dcr_1` channels — never pass the 1-D primary `dcr` as a 2-vector, that raised `cannot reshape … into shape (2)` on odd row counts). `main_window._build_aggregated_dataset` builds a **new `(aggregated N)` dataset** (non-destructive; RIMF preserved from source + `derived["rimf"]` pinned to suppress post-load auto-z; `metadata["aggregation"]`). The photon threshold dialog (`_ask_aggregation_threshold`) **remembers the last value across sessions** (`prefs["aggregation"]["photon_threshold"]`, default 3000). **Multi-channel overlay:** when the active dataset is part of an overlay, `_aggregate_active_dataset` aggregates **every channel** at the same threshold and re-links the results into a **new overlay** (new `overlay_id`, each channel keeping its `overlay_lut`/`overlay_order` + `overlay_transform`/`render_transform_2d` alignment); single datasets produce one aggregated dataset as before.
- **Localization photon count = `eco` summed over the FINAL-SCALE iterations** — for a 3-D sequence the final **lateral (xy)** + final **axial (z)** iterations (itr 8+9 in the standard 10-iteration sequence). **Not** the single last iteration (that under-counts) and **not** the sum over all iterations (over-counts; verified 0 % equal). eco is real (never NaN/0) at every iteration.
- **`core/mfx_sequence.py`** detects the photon-bearing iterations. Principled path: parse the acquisition **sequence** (`measurement.threads[].sequences[0].Itr` in the `.msr` `mfx/.zattrs`) → the iterations at the **minimum `patGeoFactor`** (tightest beam scale L) are the final-scale localization iterations; classify lateral (`Mode.pattern` square/hexagon, `mxl3`) vs axial (`zline*`, `mxa3`). `photon_iterations_for_dataset(ds)` uses `ds.metadata["mfx_sequence"]` (stamped at MSR open by `msr_reader_dialog` via `read_zarr_attrs` + `extract_sequence_from_zattrs`) when present, else `fallback_photon_iters(n_itr, dims)` (3-D → last two iterations, 2-D → last one — same result for the standard sequence). This detector is shared with the per-dimension **CRLB** photon budget (see Localization precision). Tests: `tests/test_aggregation.py` (synthetic + a regression gated on the reference Imspector files under `D:\Workspace\…\test_data_for_agg`).

## Local density
`analysis/local_density.py` — **Analyze › Local Density** + the on-load auto-compute (`compute_local_density` pref → `ds.attr["den"]`, broadcast across iterations via `derived_last`). The plugin exposes three methods; the on-load preference exposes only checkbox + radius and chooses KD-tree automatically unless the radius query is estimated to be too expensive. **Plugin ↔ preference are decoupled:** the plugin (`run_local_density`) *seeds* its dialog from the `data.local_density_*` prefs but must **never write them back** — those prefs are user-owned (changed only in Preferences) and define the standard radius for the on-load `den`; the plugin is ad-hoc exploration at different radii (`tests/test_local_density_window.py::test_run_local_density_does_not_modify_preferences`).
- **KD-tree range search** (`local_density_kdtree`, exact): `cKDTree.query_ball_point(..., return_length=True, workers=-1)`. **`workers=-1` (parallel) + `leafsize=32` is the ≈8× speedup — keep both** (serial was the bottleneck: ~2.4s → ~0.3s for 270 k 3-D locs; build is negligible, the range *count* dominates). `return_length` never materializes neighbour lists. **Counts include the centre point** (a lone localization reports 1, not 0 — so "single point in empty space" is distinguishable from genuinely void space); this differs from MATLAB `rangesearch − 1`. The voxel disk/ball method matches this (kernel covers the point's own voxel), and the voxel histogram inherently counts the point. Works for 2-D and 3-D and is the only exact, per-radius measure.
- **Voxel histogram** (`local_density_histogram_nd`, coarse + fast, runtime ∝ voxel grid not point count): bin → optional Gaussian smooth → each point gets its voxel count. Generalized to **2-D and 3-D** (`local_density_histogram_2d` is a thin wrapper). The local-density method key is `voxel_histogram`. Guarded by `_MAX_HISTOGRAM_CELLS` (20 M) — a too-small voxel raises a clear error (no silent giant allocation). Use this when a coarse voxel proxy is enough.
- **Voxel disk/ball radius count** (`local_density_voxel_radius_count`, approximate radius count): bin → convolve the voxel-count grid with a physical disk/ball kernel → sample each point's voxel. Usually much faster than exact KD-tree for dense data, while retaining a radius-like interpretation.
- **Neighbourhood shape.** KD-tree and voxel-ball count neighbours inside a **sphere/ball** (2-D: disk) of the radius; only voxel-histogram uses a **cubic** voxel. The dialog labels them accordingly and defaults to the exact **KD-tree ball**. The `LocalDensityOptionsDialog` order is kdtree → voxel_radius → voxel_histogram.
- **Result window** (`LocalDensityImageWindow`): the plugin's added value over the on-load `den` attribute is a **spatial density map** + radius/method/dimension exploration (it recomputes and overwrites `ds.attr["den"]`, but never touches the prefs).   - **3-D view.** For 3-D data (`compute_local_density` now also returns `points_valid`/`density_valid`; `run_local_density` passes them + `dimensions`), the **View** combo offers a **3-D scatter of the localizations coloured by density** (`pyqtgraph.opengl` `GLScatterPlotItem` + grid + axis; density → colours via `make_colormap(...).map`, 1–99 % robust range; points recentred by `_anchor`, decimated to `_MAX_3D_POINTS`). ## Channel flatten (overlay → single dataset)
**Process › Channel… › Flatten** (between *Split…* and *Overlay*; `actionChannelFlatten` → `main_window._flatten_active_channel_group`). Combines the **active multi-channel overlay** into one **non-overlay** dataset so convolution / particle analysis can run over the *combined* localizations. `core/channel_flatten.py::flatten_overlay(datasets)` (pure, Qt-free, unit-tested) concatenates every channel **in place** — each channel's overlay transform **baked into display nm** via `display_coords` — honouring each channel's **filter mask** (only currently-visible locs). - **Attribute combination rules** (all reported to the Log): **`tid` is remapped** globally-unique — each channel's tids are dense-ranked (preserving its trace grouping) then offset past the previous channel, so the *same* tid in different channels stays a **distinct trace** (`_remap_tids`). It moved out of **Analyze › Clustering**, which now holds only the generic `DBSCAN`/`K Nearest Neighbour` placeholders.

Regression: `tests/test_hlyb_pairwise_window.py`, `tests/test_hlyb_result_window.py`, `tests/test_hlyb_staged.py`.
- **`PluginEntry` gained an optional `keywords` tuple** (Command Finder search tags). `ui/command_meta.py` is keyed by **QAction attribute name**, and a plugin action has none — so plugin metadata lives on the `PluginEntry` and `_populate_plugins_menu` stamps `command_keywords` from it alongside `command_source`. This is how the plugin is findable by `dimer` / `surface null` / `ecoli`, which are not in its label.
- **The Log line is `HlyB/D subunit pair analysis on '<name>': …`** and carries the `method_data` payload. `method_text.py` matches **both** it and the pre-plugin `HlyB staged short-range population (3D) on '<name>':` prefix, so method text still generates from an older Log.
- **Generate Method Text is self-contained** — `_render_hlyb_staged_short_range` emits *Input data · Site inference · Spatial null and observable · **Parameters** · **Definitions of reported terms** · Result · Dependence on the null stratification · Interpretation and limitations*. `_hlyb_parameter_block(params)` lists every operator-set value with what it controls (so a run is reproducible from the text alone); `_HLYB_DEFINITIONS` defines *inferred labelling site · spatial component · band · observed/null ratio · null replicate distribution · positive excess (peak/centroid/median) · null stratum · sensitivity audit* operationally — what each is computed from, never what it is believed to mean biologically; `_hlyb_limitations_block` appends the run's own recorded limitations. Regression: `tests/test_hlyb_staged.py::test_method_text_documents_parameters_and_terms`.
- The dialog opens on the project's fixed **RIMF 0.67** (`runner.PROJECT_RIMF`), not the dataset's auto-estimated value; the user can override per run. The last-used config is remembered on `state._hlyb_staged_cfg`.
- **Staged short-range population (3D)** (`analysis/hlyb_staged.py`, `ui/hlyb_staged_dialog.py`, `actionHlyBStaged3D` → `_run_hlyb_staged_analysis`): pulls raw last-valid `loc/tid/tim`, applies the explicitly configured RIMF once (project default 0.67), and reports evidence for a **population-level short-range excess**, never a fitted/assigned molecular dimer distance. Stages: trace centroids + measured SEM → uncertainty-aware complete-link consolidation of repeated traces into label-site estimates (default hard diameter 4 nm; no LoG/DBSCAN; time has no maximum-gap cutoff) → coarse spatial/cell components (no cross-component pairs) → exact pair profile → conditional rod-surface null. The null fixes every observed axial coordinate and locally permutes complete transverse membrane coordinates within axial-rank strata, preserving exact site count, axial density, local radial support, one-sided visibility and component boundaries instead of filling 3-D cubes. The primary test is pre-declared at 8–25 nm (8 nm = twice the default same-site diameter); the result reports observed/null ratio, conditional-randomization p, and positive-excess peak/centroid/median explicitly as distribution descriptors. Independent-component bootstrap is emitted only for ≥3 retained components. A mandatory sensitivity audit varies same-site diameter 3/4/5 nm, null stratum 32/64/128 sites, and the component-link distance by ±25%. The result window shows XY/XZ/YZ raw traces/inferred sites/one null draw, observed + 95% null band, excess curve, diagnostics and limitations. `Generate Method Text` is backed by schema `hlyb_staged_short_range_3d/v1`. Synthetic rod tests verify calibrated null data and recovery of an injected 14 nm population (`tests/test_hlyb_staged.py`); `scripts/analyze_hlyb_staged_batch.py` deduplicates MSR acquisition-history copies and summarizes biological replication at the acquisition level.
- **Staged-method robustness contract.** Two flags, both requiring **every valid sensitivity variant** to pass. `robust_short_range_excess` (original) needs ratio >1 and conditional p ≤0.05. **`robust_short_range_excess_calibrated` is the one to quote**: ratio >1 **and** `band_ratio_z ≥ cfg.calibrated_ratio_z` (default 3.0). `sensitivity_valid_variants` records how many variants were evaluable, `sensitivity_passes`/`sensitivity_calibrated_passes` their individual decisions; sparse or invalid variants must never be silently counted as successful.
- **Staged-method: do NOT quote `band_p`.** It is bounded below by `1/(null_replicates+1)` (0.01 at the default 99) and was measured **anti-conservative** — re-testing 40 surrogates drawn from the method's own null called 15 % significant at a nominal 5 %, because each surrogate is re-segmented and re-stratified so the strata never exactly match. `band_p_resolution` carries the floor so a *censored* p never reads as a *measured* one. Report instead **`band_ratio` against `null_band_ratio_mean ± null_band_ratio_sd`**, scored by **`band_ratio_z`** (`_null_ratio_distribution`: each null replicate over the leave-one-out mean of the others — same construction as the observed ratio, so it is calibrated and unbounded). On the reference dataset it reads 48.3, against 45.9 measured externally from fresh surrogates. It is a ratio-scale rescaling of `band_z`, **not independent evidence** — its value is that it is in the units quoted and exposes the null spread.
- **Staged-method: `band_ratio` is conditional on `null_stratum_sites`, the centroid is not.** The stratum sets the axial window inside which the randomization destroys structure, hence how much structure the null absorbs. `_stratum_profile` (config `run_stratum_profile`/`stratum_profile_sites`, default 16/32/64/128/256) varies the **null alone**, holding inferred sites and components fixed — unlike the sensitivity audit, which varies them too. On the reference dataset the ratio moves **1.14 → 4.47** (3.9×) while the positive-excess centroid moves only **11.41 → 14.53 nm**. `band_ratio_is_stratum_conditional` flags a spread above `stratum_profile_ratio_tolerance` (1.5). **Always quote the ratio together with its stratum; the excess *location* is the stable descriptor.** Component linkage, by contrast, is not a sensitive knob (centroid 13.5–13.8 nm, ratio 2.0–2.2 across `cell_link_nm` 90–250).
- **Staged-method uncertainty: prefer `centroid_sensitivity_range_nm`** (min–max centroid over the valid audit variants, 12.27–14.17 nm on the reference file) over the component bootstrap. `_component_bootstrap` resamples retained components, so with the typical 3 it cannot express between-cell variance; it sets `narrow_ci_warning` when `n_components < 5` and the UI/method text say so. It shares `_band_descriptors` with `_excess_summary` rather than fabricating a `np.vstack([m, m])` two-replicate null (whose internal p/z/sd were meaningless).
- **Staged-method validation benchmark.** The current 2026 project collection contains 13 analyzable acquisitions: 11 pass every valid sensitivity variant, and all 10 acquisitions retaining at least 150 sites pass. The acquisition-level median positive-excess centroid is 14.01 nm (13.88 nm in the ≥150-site subset). These are dataset-specific regression/interpretation benchmarks, not hard-coded acceptance values or proof of a unique molecular linkage distance. **These counts predate `robust_short_range_excess_calibrated`** and were scored on the original nominal-p flag — re-run `scripts/analyze_hlyb_staged_batch.py` before quoting a pass count against the calibrated criterion.
- **Staged-method controls (do not re-derive).** Reference dataset `260626-155951_minflux_mfx.mat` at `min_loc=10`, RIMF 0.67: 3382 sites from 3923 traces, 3 components, ratio 2.041, centroid 13.52 nm, robust on 7/7 variants. Synthetic rod with **independent sites only → ratio 1.058, p 0.26** (no false positive); **planted 14 nm → centroid 14.06 nm**; **planted 20 nm → centroid 20.02 nm** — the centroid is an unbiased estimator of a planted scale. Same-emitter contamination of the 8–25 nm band is low: of time-adjacent repeat pairs (median 3.15 nm), 61.6 % are merged away by the 4 nm diameter, 28.6 % land in the displayed-but-untested 4–8 nm gap and **only 9.4 % reach the test band** — which is what justifies `short_range_lo_nm = 2 × site_merge_nm`. An "envelope scramble" of the real data is **not** a fair negative control (it manufactures 30–50 nm blobs at exactly the scale the null destroys).
- **All three 3-D methods agree on the reference dataset** — staged positive-excess centroid **13.52 nm**, pair-distance model fit median **12.75 nm**, template matching median gated pair **13.39 nm** — from independent premises (model-free excess / parametric blurred-distance likelihood / geometric template gate). They are complementary, not redundant: staged is the defensible **detection** but has no structural model so it **cannot address trimer-vs-dimer**; the pair fit is the only one testing architecture (it rejects the six-site trimer by 547–1499 AIC); template matching is for per-complex **visualization** only (its gate passes 99.96 % of random hard-core triangles at n=3).
- **Staged-method temporal limitation.** Acquisition times are retained and site consolidation has no arbitrary maximum time-gap cutoff, but `hlyb_staged_short_range_3d/v1` does **not** yet implement a full temporal emitter model (for example dynamics/drift-corrected clustering or BaGoL-style inference). Treat unresolved temporal emitter assignment as the principal stated limitation of this version.
- **Earlier clustering/template family (retired from the menus, code kept — see above).** `analysis/hlyb_clustering.py` is a pure-NumPy/SciPy port of `minflux_hlyb_analysis.m` (3-D) + `Ecoli_dimer_analysis_2D.m` preprocessing (Qt-free, unit-tested). It pulls **raw** last-valid loc + tid via `mfx_get(ds, "loc_x|loc_y|loc_z|tid", itr="last", vld_only=True)` (metres; z-scaling applied inside, not RIMF-baked). Core pipeline: (1) `locate_subunit_centers` groups traces → sub-units (trace-centroid loc-count + local-density pass; Laplacian-of-Gaussian blob pass via `_fspecial_log`; DBSCAN-merge pass), with `Dunit` from config or `2·median(estimate_trace_size)`; (2) `analyze_hlyb` DBSCANs sub-unit centres (eps `2·d_1b2b/√3`, minpts `min_unit_count_per_HlyB`) into HlyB structures and measures within-structure pair distances. **DBSCAN is hand-rolled** (`dbscan()` via `scipy.spatial.cKDTree`, MATLAB minpts-includes-self semantics) — `sklearn` is not a dependency.
- **3-D** (`analyze_hlyb`): the original; uses `z_scaling_factor` (defaults to the dataset RIMF). **Template matching (3D)** evaluates structurally constrained six-subunit candidates, rejects threshold failures and overlapping candidates, and reports its candidate/pass/rejection QC. The result carries `point_source_indices` so source-dataset attributes remain row-aligned after analysis preprocessing.
- **2-D** (`analyze_hlyb_2d`): first runs the **E.coli border-removal preprocessing** — `compute_border_mask` builds a coarse XY histogram (`mask_pixel_size_nm`), Gaussian-smooths, Otsu-binarizes (`_otsu_threshold`), hole-fills + median-filters into a per-cell mask, then erodes inward by `border_size_nm` (a `_disk_struct`); **whole traces touching the eroded margin are dropped** (where 2-D distances are unreliable). z is forced to 0, then `analyze_hlyb` runs on the interior. Result carries `border_points_nm`/`n_border_traces`/`n_total_traces`/`is_2d`; `point_source_indices` and border-source indices preserve source-row identity. The result initially opens in XY and draws border-excluded locs faint orange. Thin/sparse fields may be fully eroded by the default 200 nm border (correctly → 0 interior).
- **Result scatter controls** (`ui/hlyb_clustering_dialog.py::HlyBResultWindow`): all XY/XZ/YZ/3D views share `raw loc`, `sub-unit detection`, `template match`, and `pair link` visibility controls. Turning off `template match` makes every visible sub-unit gray; turning off `pair link` hides links and their one-decimal distance labels together. Labels appear only when a projected link is at least 42 screen pixels long and are capped at 100, keeping overview and 3-D rendering legible. Raw-localization display is deterministically thinned above 100,000 points; this is display-only and does not alter analysis results.
- **Scatter navigation and colour**: the context menu mirrors Loc Scatter Plot (`View as` XY/XZ/YZ/3D, `Color by`, `Colormap`, `Black Background`, `Reset View`). A shared world-space centre + nm-per-pixel scale preserves the viewed location and zoom while changing projection; the unshown coordinate retains its last shared centre. `Color by` affects **raw localizations only** and uses the same preference-filtered numeric raw/derived attribute list as Loc Scatter (`plot_attribute_names`, excluding `ftr`/`idx`), with `tid` guaranteed and selected by default. Values are aligned through `point_source_indices`; cfr/efc use their effective iteration. Template/sub-unit colours are intentionally independent of raw-localization colour and colormap choices.
- **Sub-unit hover**: hovering a visible sub-unit in 2-D or within 11 screen pixels in 3-D shows one custom tooltip containing full X/Y/Z centre coordinates in nm and the one-based Template ID (`—` when unmatched). In 2-D, the `ScatterPlotItem` must remain `hoverable=True, tip=None` both at construction and on every `setData`: pyqtgraph's default tooltip otherwise follows the custom one with `x`, `y`, and `data`, where `x/y` are projected plot coordinates and `data` is only the internal zero-based sub-unit row index, not a scientific measurement. Hover callbacks must test `points is None or len(points) == 0`, never `not points`, because pyqtgraph may supply a NumPy array whose truth value is ambiguous.
- **Distance histogram**: template-gated distances are blue; **show all (remove template gating)** overlays in gray all pair distances among detected sub-unit centres before template assignment. The range is adaptive with a 40 nm minimum; bin width is 0.1–10 nm in 0.1 nm steps, hover reports bin centre/count, and changing the width preserves the exact current X/Y field of view. **show lognormal fit** adds a fitted curve, dashed mean line, and μ/σ/RMSE report for the displayed target series. The custom context menu provides the shared Histogram horizontal/vertical/unconstrained Zoom and Reset View operations; the old median and structural-prior reference lines are intentionally absent.
- `HlyBClusteringDialog(mode=)` is the modal parameter picker (`HlyBConfig` dataclass; basic-unit-size 0 = auto); `HlyBResultWindow` is modeless. Its vertical splitter gives the scatter/histogram minimum heights of 330/230 px, a 3:2 stretch, and non-collapsible panes so the scatter and fit report remain visible. Regression coverage: `tests/test_hlyb_clustering.py`, `tests/test_hlyb_result_window.py`.

## Convolution segmentation (2D + 3D)
**Analyze › Segmentation › Convolution… / Convolution (3D)…** — general geometry-kernel matched-filter detection (NPC is one special case).
- **Detection runs in DISPLAY coordinates, not raw `loc_nm`.** ROIs live in display space (loc_nm + overlay transform), so every detection tool that places ROIs on a dataset (NPC 2D `_segment_npc_2d`, Convolution 2D/3D `_load_xy`/`_load_xyz`, NPC-detection-Wanlu) pulls localizations via `core/roi_crop.py::display_xy_filtered(ds)` / `display_xyz_filtered(ds)` (= `display_coords` + filter mask + finite) — **never** raw `ds.loc_nm`. Using raw coords put detections at the wrong place for an **overlay channel** whose transform ≠ identity (the detected NPC/rectangle ROIs were offset from the displayed channel). No-op for a non-overlay dataset (transform is None). Regression: `tests/test_particle_set.py::test_display_xy_filtered_applies_overlay_transform`. (Also fixed: `particle_extract` recorded the overlay transform via `np.asarray(dict)` — now `overlay.py::transform_to_matrix4` extracts the bare 4×4; a dict crashed *Collect* on an overlay with "float() argument … not 'dict'".)
- **2D** (`analysis/conv_segmentation.py` + `ui/conv_segmentation_dialog.py`): a geometry-model registry (`GEOMETRY_MODELS`: ring/disk/gaussian/log, each a `ParamSpec` list) → L2-normalised (optionally zero-mean) kernel → `fftconvolve` of the rendered XY histogram (rescaled to unit max) → NMS. SMAP-aligned options: `sqrt` stabilize, DoG band-pass, ring validation (reject solid blobs by inside/outside-ring loc-count ratios). Detection list shows `r=` (the matched-filter response fraction in [0,1], thresholded by *Min response*). Two-phase: geometry/pixel rebuild the response (debounced), threshold/separation re-run only NMS. Adds **rectangle ROIs**.
- **3D** (`analysis/conv_segmentation_3d.py` + `ui/conv_segmentation_3d_dialog.py`): genuinely 3-D — `histogramdd` → 3-D kernel (`shell`/`ball`/`gaussian`/`log`) → `scipy.signal.oaconvolve` → 3-D NMS (anisotropic-voxel-aware). Viewed as a **2×2 orthoviewer** (XY/YZ/XZ response slices + linked draggable crosshairs + an experimental pyqtgraph.opengl 3-D pane) — convolve-in-3D-then-slice, no MIP info loss. `DEFAULT_MAX_VOXELS=8_000_000`; `suggest_voxel_sizes()` auto-picks a feasible voxel size on open (multi-µm FOVs would otherwise blow past the cap and blank the view). Adds **3-D point ROIs** (`main_window.add_point_rois_3d`). **Next phase: merge the 2D/3D dialogs.**
- **Per-layer Brightness/Contrast:** both convolution dialogs (and future merged one) drive the render viewer's `ui/brightness_contrast_dialog.py` via the shared `ui/layer_brightness.py::LayerBrightness` controller — one always-on-top palette re-targeted across named layers (Response / Data). The 3-D Data layer slices the cached raw counts volume with a white-alpha LUT over the inferno response.
- **Defaults + persistence (2D dialog).** Show-layer defaults: **Detection + Data on, Response off**. All parameters — model + per-model params (via `_model_params`), pixel/response/separation/box/ring-validation, the option checkboxes, **and the three show-layer checkboxes** — persist across sessions in `prefs["conv_segmentation"]` (`_save_prefs` on `closeEvent`, `_restore_prefs` on open). Fresh install (no prefs) → the ring/NPC diameter default is **100 nm** (`GEOMETRY_MODELS["ring"]` `ParamSpec` default; range 10–5000, so the user can dial 80–120 for NPCs). Regression: `tests/test_conv_segmentation.py`.

## Particle Average
**Analyze › Segmentation › Particle Average…** (`ui/particle_average_dialog.py` + `analysis/particle_average.py`) — a **particle accumulator**: collect box (rectangle) ROIs (e.g. detected NPCs) into independent **re-zeroed** point clouds, keep appending from many datasets/files into one pool, then average (template-free / template-provided / NPC two-ring Wanlu). All three are **3-D-aware**. Modeless QDialog per the window convention. **No active dataset is required to open it** (`_show_particle_average` has no data guard; the window tracks the active dataset dynamically via `_active_dataset()` and handles `None`) — a load-only workflow (particle set / data+ROI pairs) is fully supported; the `dataset_idx` ctor arg is vestigial/unused.
- **Particle data model** (`core/particle_set.py::ParticleData`): `points` = `(M,3)` **re-zeroed display nm** (XY to box centre, Z to median) — the **authoritative** cloud the averaging consumes; `loc` = optional `(M,3)` **raw metres** (Z not RIMF-baked) — **provenance only, never re-corrected**; `tid`, `unit_id` (sub-unit, 0=unassigned); `attrs` = open dict of per-loc columns; `meta` = recipe (`rezero_offset`, `rimf`, `z_scale`, `transform_4x4`, `source_version`). `n_locs` is a property.
- **Extraction** (`core/particle_extract.py::extract_particles(ds, records)`) is the **single source of truth** shared by *Collect from active dataset* and *Load data+ROI pair*: rectangle-only, ≥`MIN_LOCS_PER_PARTICLE` (5), filter-mask honoured, crops `roi_crop.display_coords` (RIMF/overlay baked), re-zeroes, captures **every** per-loc attribute (`_capturable_attr_names`, archival — independent of Preferences visibility) + raw loc (`_raw_loc_m` from `ds.attr["loc"]`, metres). The Wanlu `tid→unit_id` map comes from `ds.derived["npc_wanlu"]["raw6"]`.
- **Save/Load = HDF5 particle set** (`save_particle_set`/`load_particle_set`/`is_particle_set_file`, `format="minflux_particle_set"`): pooled equal-length 1-D column datasets under `/localizations` keyed by a `particle_id` column (mirrors `AttrStore`), per-particle metadata under `/particles`. Both coordinate frames stored — `xnm/ynm/znm` (float32, authoritative) + `loc_x/y/z` (float64 metres, provenance). **Save dialog** (`ParticleSaveDialog`): `content="all"` (loc + raw loc + all attrs) vs `"loc_tid"` (coords + tid + unit only); `include_raw_loc`. Particles from different datasets are **unioned** (missing attr columns → NaN). **Load dialog** (`ParticleLoadDialog`): (1) a particle-set `.h5`, or (2) a **data + detection-ROI(.json) pair** — `load_any_dataset` loads the dataset off-viewer (default RIMF recorded in meta, not the async post-load estimate) and `records_from_roi_json` parses the saved ROIs, then `extract_particles` crops; the dataset need not be open. Tests: `tests/test_particle_set.py`.
- **NPC 8-fold template model** (template-provided). `geometry_template_image` gains `kind="npc"` — a **ring of N Gaussian corner blobs** (`symmetry`-fold, default 8; params `diameter_nm`/`corner_nm`/`symmetry`). Built on the ring model but it breaks the ring's continuous rotational symmetry down to Cn, so image cross-correlation can **phase-lock** each particle to the nearest corner and the average resolves the N discrete sub-units instead of a smeared ring. Kept **local to the plugin** (`particle_average_dialog.py::_NPC_TEMPLATE_PARAMS` / `_template_model_spec`, `_TEMPLATE_MODELS += "npc"`) — deliberately **not** in `cs.GEOMETRY_MODELS` (which the conv-segmentation dialogs enumerate and which needs a `make_kernel`). Selecting it **auto-enables `correct_tilt`** (`_on_geom_changed`), so it ships the axial-tilt handling; still user-toggleable.
- **Axial tilt (all image fitters).** Template-free / template-provided take `correct_tilt` (dialog: "Correct axial tilt (3-D, per-particle PCA)"): each particle is **PCA-untilted** before 2-D registration — `particle_average.py::estimate_tilt_normal` (smallest-variance eigenvector = plane normal) + `flatten_tilt` (rotate normal→+Z via `_rotation_a_to_b`, about the centroid) in `_prepare_particles`. No-op for planar/2-D data (normal already +Z); result carries `mean_tilt_deg`. This makes the image fitters handle tilted 3-D particles instead of only XY-projecting them (Z was previously translational-only). The **NPC two-ring (Wanlu)** method handles tilt natively via its fitted per-NPC normal.
- **Alignment performance (batched + multi-core).** The template-free / template-provided image aligners are the hot path (`n_iter × n_particles × n_angles × (render + FFT)`). Two speedups, both **bit-identical** to the old per-angle loop (verified in `tests/test_particle_average.py`): (1) **`_align_one` batches the whole rotation search** — all `A` rotations are rendered in one `np.histogramdd` (angle axis + the two spatial axes) + one `scipy.ndimage.gaussian_filter(sigma=(0,s,s))` + one batched `np.fft.rfft2`/`irfft2` over the `(A,n,n)` stack, instead of `A` tiny per-angle calls (rendering was ~60 % of the time, dominated by Python overhead across tens of thousands of calls). (2) **The per-particle alignment runs on a `ThreadPoolExecutor`** (`_align_all`, `n_workers` param, `None`→all CPUs, capped to particle count) — threads only help *because* the batched numpy/scipy ops release the GIL for long enough; the pre-batch per-angle loop was actually **slower** threaded. The template `rfft2`+norm are precomputed **once per iteration** (`_xcorr_shift_pre`), not per angle. Iterations stay sequential (each needs the previous mean); `on_done()` progress ticks run in the calling thread (thread-safe). Net ≈ 6× on a 16-core box (~2× batching × ~2.7× threads). The dialog needs no change — `average_particles(**kwargs)` defaults `n_workers=None` → all cores. GPU (CuPy) was considered but not added: the arrays are small and it needs a heavy optional dep + a GPU. Regression: `tests/test_particle_average.py::test_parallel_alignment_matches_serial`.
- **Template-free convergence / early stop.** `average_template_free` is an EM-style coordinate ascent (align-all maximises the mean cross-correlation **score** vs the current reference, then the reference is rebuilt as the mean), so the score is monotonically non-decreasing to a fixed point — empirically it **plateaus within ~2–5 iterations** (the reference stops changing, later iterations reproduce it). It now **early-stops** when the *relative* score gain between iterations falls below `tol` (`(score−prev) ≤ tol·|prev|`, the EM/MLE rule à la `sklearn.GaussianMixture(tol=)`); `n_iter` is only a **safety cap**. `DEFAULT_N_ITERS=30`, `DEFAULT_CONV_TOL=1e-4`; the result dict carries `iterations` (actual) + `converged` (bool) + `score_history`. **`tol=0` disables early stop** (run the full `n_iter`) — used by tests that assert exact iteration/progress counts (`test_average_reports_progress`, `test_template_free_converges` pass `tol=0`; `test_template_free_early_stops_on_convergence` checks the stop). The dialog's **"Max iterations"** spin is `1..100` (default 30) and a **"Convergence tol"** spin (`_conv_tol`, default 1e-4, 5-dec) feeds `tol`; the result label reads `template-free, N iter (converged|max iter)`. Template-**provided** is a single pass (no `n_iter`/`tol`).
- **Wanlu goodness-of-fit gate + metrics table.** `average_npc_wanlu(..., min_gof=)` (dialog: "Min goodness of fit", R²) pools **only** NPCs whose two-ring fit explains ≥ `min_gof` of the point spread; it always returns a `table` (one row per fitted NPC) of metrics **recomputed on the best fit** by `_fit_metrics`: `radius`, `rim` (radial-residual σ), `inter` (inter-ring), `tilt` (deg), `gof` (R² = 1−SS_res/SS_tot, point-to-ring residuals), `rmse` (nm, 3-D point-to-ring), `nrmse` (= rmse/radius), `accepted`. Shown in `ParticleFitTableWindow` (modeless, **Save CSV**) — surfaced even when nothing passes the gate, so the user sees *why*. The gate is the guard against the method's inherent two-ring/N-fold model bias (a bad fit is no longer accepted on finiteness alone). Tests: `tests/test_npc_wanlu.py`, `tests/test_particle_average.py`.
- **Multi-channel averaging (overlay).** When the active dataset is one channel of an **overlay**, the **"Combine overlay channels (apply transform)"** checkbox (default **on**; template-free / template-provided only) aligns/averages using the *active* (reference) channel and **replays each particle's transform onto the other channel(s)**, producing a combined **averaged overlay**. Enabler: `average_template_free`/`_provided` now also return `particle_transforms` — a per-particle **4×4** mapping the original re-zeroed points → the pooled frame (`_particle_prep` builds the tilt+centre matrix; `_matrix_2d` the 2-D rigid part; `M_i = M_2d @ M_prep`). `apply_particle_transform`/`pool_transformed` replay them. Collection: `_collect_multichannel` extracts the reference particle per ROI then `core/particle_extract.py::channel_points_in_roi(other, rec, rezero_offset)` pulls each other channel's co-located points (overlay channels are aligned in display space; **all channels re-zeroed by the reference offset** so inter-channel geometry is preserved), stored parallel in `_channels_by_particle`. The worker pools each channel via the reference transforms; `_on_done` builds the overlay through `main_window.add_particle_average_overlay(channels, luts=…)` (reference centred on its median, the **same** offset applied to every channel; per-channel LUT from the source overlay). Note: for a symmetric reference (e.g. 8-fold NPC) the alignment's rotational ambiguity can smear an asymmetric second channel — inherent to the method, not a bug. **Wanlu** stays single-channel (its per-NPC two-ring fit isn't wired to export a replayable transform). Tests: `tests/test_particle_average.py::test_particle_transforms_reproduce_pool_and_map_channels`, `tests/test_particle_set.py::test_channel_points_in_roi_rezeroes_by_reference_offset`.
- **Result dataset + on-load skip.** The averaged super-particle is added via `main_window.add_particle_average_dataset` (`build_localization_dataset` with **`tid=None` → every loc is its own synthetic trace**; RIMF pinned 1.0 + `derived["rimf"]` set to suppress the auto-anisotropy estimate; `metadata["particle_average"]=True`). The post-load steps `_post_load_loc_prec` and `_post_load_density` **skip `particle_average` datasets**: per-trace precision is meaningless (placeholder tid), and the pooled cloud is a **dense superposition at the origin** — the KD-tree range-count auto→voxel heuristic (`local_density._estimate_radius_query_work`) estimates work from bounding-box *volume* assuming uniform density, so it undershoots on a dense-core/box-extent cloud and can run the exact all-core KD-tree at ≈O(N²) for minutes (this was a full-CPU, UI-frozen ~3-min hang after averaging). Regression: `tests/test_post_load.py`.

## Drift correction (plugin)
**Plugins › Drift Correction** — time-window auto-correlation drift correction, a faithful Qt-free reimplementation of **pyMINFLUX** (`pyminflux.correct.drift_correction_time_windows_2d/3d`), itself from Ostersehlt et al. 2022 (DNA-PAINT MINFLUX, Nat Methods 19:1072). Core `analysis/drift_correction.py` (pure NumPy/SciPy, unit-tested); window `plugins/drift_correction/drift_correction_window.py` (modeless via `show_modeless`).
- **Algorithm** (`estimate_drift` → `drift_correction_time_windows_2d/3d`): split the acquisition into `Ns` equal windows of length `T`; render each window (histogram + Gaussian blur, `fwhm=3·s`); FFT-cross-correlate every window pair (up to `D=Ns` apart); refine each correlation peak by 20-iteration weighted centroid; solve a **roughness-regularised least-squares** (`lse_distance`, BFGS) per axis for the per-window drift trajectory; mean-subtract; linearly interpolate onto every localization's time. Returns a `DriftResult` (per-loc `dx/dy[/dz]` nm, window-centre trajectory `ti/dxt/dyt[/dzt]`, `time_window_s`, `n_windows`, `rms`). The render uses a **fast histogram+blur** instead of pyMINFLUX's per-loc Gaussian splat, but replicates pyMINFLUX's **image orientation** (transpose + y-flip; z direct) so the **sign convention is identical** — verified by a synthetic drift-recovery test (`tests/test_drift_correction.py`, corr > 0.9).
- **Parameters read from the data** (last-valid localizations only, via `core/loader.py::mfx_get(itr="last", vld_only=True)`): **x, y[, z]** display coordinates in **nm** (`xnm`/`ynm`/`znm` — `znm` includes RIMF, so the estimate + output are in the displayed frame); **t** time in **seconds** (`tim`); **tid** trace ids (used only for the auto time-window heuristic). UI-set: **render resolution** `s` (nm, default 5), **time window** `T` (s; `Auto` = pyMINFLUX heuristic `n_traces·W·H/3e6` clipped to `[600, min(span/2, 3600)]`), and **dims** (Auto/2D/3D). Spatial ranges default to the data extent.
- **Output = a NEW corrected dataset** (non-destructive, so before/after compare): `x_corr = x − dx`, etc., baked into `build_localization_dataset` (carries canonical per-loc attrs `efo/cfr/dcr/eco/ecc/efc/fbg/…`; RIMF pinned **1.0** + `derived["rimf"]=1.0` to suppress post-load auto-z since coordinates are final; `metadata["drift_corrected"]=True` + `["drift_correction"]` provenance). Estimation runs **synchronously** with a wait cursor (typically a few seconds; a render-grid cap `_MAX_RENDER_CELLS=64M` guards huge FOV × fine resolution). Tests: `tests/test_drift_correction.py`, `tests/test_drift_correction_window.py`.

## Method-text generator & log history
- **Log history.** `AppState` keeps a bounded `_log_history` (≤ `_log_history_max`, exposed via `state.log_history`); `state.log(message, level="INFO", *, dataset_idx=None)` tags each entry with the resolved dataset (`dataset_idx`/`dataset_name`) so events can be attributed to a dataset after the fact. `add_dataset` emits a parseable tagged load-summary (`Loaded dataset '<name>': <valid> valid locs, <n> iteration(s), <t> trace(s), <d>D [<ver> (<container>)].`).
- **Status-bar progress for long computations.** The main-window status label is driven by `AppState.status_message`. `state.status_progress(header, fraction=None)` pushes a concise `"<header>…"` / `"<header>…  NN%"` line there (strips a trailing `…`/`.`). The `state.task(msg)` context manager (Log header + refreshing ASCII bar) now **also mirrors to the status bar** — entry emits the header, each `t.update(f)` emits `"<header>…  NN%"`, and exit emits `"<header>: done."`/`"<header>: failed."` — so any `task()`-based computation (e.g. FRC) is traced in both places for free. The **post-load chain** surfaces each heavy step to the status bar (`_run_post_load_computations` → `Processing '<ds>'`; `_post_load_rimf_estimate`/`_post_load_loc_prec`/`_post_load_density` announce their step; `_post_load_finalize` → `Finished processing '<ds>'`), and the worker-based averagers route their `progress` callback through `status_progress` (+ done/failed lines): both the Analyze-menu **NPC (Wanlu) averaging** (`_on_wanlu_avg_progress`) **and the Particle Average plugin** (`particle_average_dialog._on_progress` — its progress previously went to the Log only, so a multi-minute average showed nothing in the main window). Regression: `tests/test_status_progress.py`.
- **Log window auto-opens once, placed off the menu.** `state.log_message` → `main_window._on_log_message` opens the Log window the **first** time anything is logged (so it appears "when events start"), but places it with `modeless.place_beside(self._log_win, self, prefer=("below", …))` and then `raise_()`/`activateWindow()`s the **main** window — so the log is visible beside/below but never covers the menu bar or steals focus (the old bug: it popped centred over the main window). Fires once (later messages append via the window's own `log_message` connection; a user-closed window is not forced back). `LogWindow.__init__` **replays `state.log_history`** so the just-logged message + any earlier ones appear. Regression: `tests/test_log_window.py`, `tests/test_post_load.py`.
- **On-load window placement.** `_on_dataset_added` opens the **render view first**, then places the **Dataset-Information** window **beside** it (`place_beside(win, render_or_main, prefer=("right","below","left","above"))`) instead of on top. `modeless.beside_position(anchor, avail, size, *, margin, prefer)` is the **pure, unit-tested** geometry (exclusive `(l,t,r,b)` rects): first `prefer` side where the window fits fully in the available screen area, else the first side **clamped** on-screen — so an anchor in the top-left goes right/below, one in the bottom-right goes left/above, never off-monitor. Best effort (no forcing, never throws). Regression: `tests/test_window_placement.py`.
- **Startup / MSR-reader placement.** `modeless.corner_position(avail, size, *, align, margin)` is the **pure, unit-tested** corner geometry (`center`/`top_right`/`top_left`/`bottom_*`, clamped on-screen) — **or** `align` can be a `(fx, fy)` **fraction pair** (CSS `background-position` semantics: `fx=0` flush-left … `fx=1` flush-right, `fy=0` flush-top … `fy=1` flush-bottom, never off-screen). `ensure_on_screen(window, owner, *, align="center")` uses it (owner's screen → screen under cursor → primary; shrinks an oversized frame first). The **main window** opens at **`align=(0.75, 0.25)`** on first show (`showEvent`, `_positioned` guard) — 75 % toward the right edge, 25 % down (= 75 % up from the bottom): upper-right but nudged toward centre so child windows (render, Log, MSR reader) have room to the left/below without hugging the corner. Parented modal dialogs (e.g. the Shift+D crop dialog) centre on the main window and follow it. The **MSR reader** (`msr_reader_dialog.showEvent`, non-owned 980×860) then opens in the top corner **opposite** the main window's side (main center on the right half → `top_left`), so it clears the main window + Log (which stack together) instead of centering on top of them — fully clear on a wide monitor, only a thin top-strip overlap on 1080p (main strip is 1096 px wide, so both can't sit fully side-by-side there). Regression: `tests/test_window_placement.py` (`test_corner_*`).
- **Generator.** `analysis/method_text.py` is a pure-Python regex **rule registry** (no Qt, unit-tested in `tests/test_method_text.py`). Each rule maps a log message to a prose sentence grouped by stage (`STAGE_ORDER`), and may attach citations; unmatched events are kept verbatim under a guessed stage. Rules can read the dataset's current metadata via `_ds_for(state, ev)` for richer detail than the log string carries. **Citations are `(reference_text, url|None)`**: paper-backed methods (StdDev→Ostersehlt 2022, CRLB→Mortensen 2010, FRC→Banterle 2013 + Nieuwenhuizen 2013) carry a **verified DOI**; custom in-house methods (anisotropy, NPC) carry an inline methodology note with `url=None`. Two formatters share `_collect`: `generate_method_text` (plain text, DOI inline) and `generate_method_html` (DOI as `<a href>` hyperlink, anchor text = the URL so plain copy keeps it).
- **Plugin UI** (`plugins/generate_method_text/`): `MethodEventSelectionDialog` lists events **oldest→newest (same order as the Log)** and scrolls to the bottom; pre-checking is **overlay-aware** — `_auto_check_indices` pre-checks the active dataset, or, when it belongs to an overlay, **every channel** in it (`core/overlay.py::overlay_members`), so the whole multi-channel acquisition is selected regardless of which channel is active. Generate → `MethodTextDialog`, an editable rich-text `_LinkTextEdit` (QTextEdit) that opens a DOI on click, with Copy (rich+plain via `QMimeData`) and Save (`.txt`/`.html`).
- **MSR overlay reporting.** The MSR "Open in MINFLUX viewer" path (`msr_reader_dialog.py::_record_overlay_load_event`, only for ≥2 channels) stamps each channel's `metadata` with `overlay_channels`/`overlay_reference`/`overlay_alignment_mode`/`overlay_bead_excluded` and emits one parseable, **overlay-tagged** Log event (`MSR overlay loaded from '<file>': N channel(s) …; reference channel '<ref>'; channel alignment: <mode>; beads: …`). The `_render_msr_overlay` rule expands it by walking `overlay_members` + each channel's `metadata["overlay_transform"]` (already stored at import): channel list + per-channel properties, the reference channel, bead selection (all / N user-excluded), and per moving-channel **translation per axis + clockwise/counterclockwise XY-rotation degrees (from `rotation_2x2`) + the 4×4 matrix**. Per-channel `Loaded dataset …` events (tagged to each channel) supply the individual properties.

## Copyable dialog text
`ui/text_select.py::make_labels_selectable(container)` flips all `QLabel`s under a container (and itself) to `TextSelectableByMouse | TextSelectableByKeyboard`, so value/report dialogs are copyable like the Log. Applied to the Data window, the trace-size and anisotropy dialogs; ROI Properties sets the flags directly. **Do NOT** apply it to overlay channel-row labels — they rely on click propagation to switch the active dataset.

## Scripting
ImageJ/Fiji-style ergonomics via a small `mfv` facade. Do not expose internal controller/store details to scripts.
- Script Editor plugin: `Plugins > Script Editor`; package `plugins/script_editor/`; window `ui/script_editor_window.py`. `AppState` owns `state.mfv`; `MainWindow._bind_scripting_api()` binds the active main window and installs runtime module `sys.modules["mfv"]`. Facade: `scripting.py` — `get_active_dataset()`, `get_datasets()`, `get_dataset(index_or_name_or_dataset)` (accepts a dataset by identity), `get_attr(...)`, `get_loc(...)`, `log(...)`, `show_console()`, `mfv.viewer.render/scatter/histogram/attribute_plot`.
- Execution is trusted local Python, synchronous on the Qt main thread, not sandboxed. Catch exceptions in the editor; report tracebacks to editor output + Console; never crash the app. Script-created plot windows are kept by the facade and closed on shutdown via `state.mfv.close_windows()`. Lightweight static completer only (`mfv.`, `mfv.viewer.`, `np.`, `numpy.`); no heavy completion deps (e.g. Jedi) unless asked.

## Executable builds
PyInstaller builds are platform-native; build the macOS app on macOS and the Windows app on Windows. Use `run_app.py` as the entry point (avoids relative-import crashes when PyInstaller executes a script as `__main__`). Always rebuild from a clean `build/` + `dist/` and then smoke-test source and bundle quit behavior, data open, render/scatter/histogram, MSR import, ParaView launch, TIFF loading, ROI I/O, and local density.

### Windows one-folder build
```powershell
.venv\Scripts\pyinstaller.exe minflux_viewer.spec --clean -y
```
- Do **not** add stdlib modules to `excludes` — needed transitively; removal causes boot-time `ModuleNotFoundError`.
- Current one-folder build ≈ 260 MB (tolerable; do not aggressively trim unless asked). Size drivers: PyQt6 (~76 MB), SciPy (~62 MB), NumPy/SciPy OpenBLAS (~39 MB), matplotlib (~12 MB), PIL (~11 MB), specpy (~8 MB), h5py (~7 MB).

### macOS `.app` build
Use Python 3.11 or 3.12 in Poetry (`pyproject.toml` allows `>=3.10,<3.13`). If no committed macOS spec exists, the quick build command is:

```bash
cd /path/to/minflux-viewer
poetry install
poetry run minflux-viewer              # source sanity test
rm -rf build dist
poetry run pyinstaller \
  --clean \
  --noconfirm \
  --name "MINFLUX Viewer" \
  --windowed \
  --onedir \
  --add-data "resources:resources" \
  run_app.py
open "dist/MINFLUX Viewer.app"
```

poetry run pyinstaller --clean --noconfirm "MINFLUX Viewer.spec"
